# 一起跑步

## 使用方式

管理员在用户管理中开启「一起跑步」许可，用户在设置中开启「加入一起跑步」及「公开个人主页」。普通账号还须启用并开启个人展示；站主沿用现有站主展示规则。访客可从导航进入 `/together`，查看本月总里程、参与人数和次数，切换周/月排行，在地图下方图例筛选参与者，或通过动态进入记录。最近动态复用跑步记录的时间线样式（面板里日期列的底色与面板一致，不再露出一块灰），手机图例可横向滚动。设置保存只提交有变化的字段。

动态城市由浏览器根据返回的简化轨迹和本地城市边界估算，轨迹不可用、未覆盖或识别失败时显示「未识别城市」；地图最多提供最近 500 段轨迹，因此部分动态可能没有可供识别的轨迹。轨迹只做约 0.5 米的容差简化（`ST_Simplify(geom, 0.000005, true)`，度），低于普通 GPS 误差，主要去掉重复和原地不动的点；最初是约 11 米，跑道或操场这类小圈会被削成多边形。合成数据上，跑道圈保留约 86% 的点、5 公里公路跑保留约 79%。预期只有两三人参与、每月不超过百条，所以牺牲体积换精度；最多 500 段时响应约为原来的数倍，若以后参与者变多需要重新评估上限或容差。配速缺失时显示 `—`。

## 接口与隐私

`GET /api/v1/together` 无需登录，账号须同时满足管理员许可、本人加入和公开主页三个开关，且具名展示可访问；任一条件关闭后下一次请求不再包含该用户。接口不缓存，响应带 `Cache-Control: no-store`。仅统计 `visibility=public` 的记录和路线，私人及不公开链接记录不参与任何汇总、排行、动态或地图。月度总里程及次数、周/月排行按服务端 UTC 日期计算，参与人数为符合条件的账号数。

响应包含参与者标识、昵称、头像版本、公开运动汇总、最多 20 条动态和最近最多 500 段简化路线；不包含邮箱、备注、原始文件或身心健康数据。地图颜色从用户 ID 稳定派生；轨迹留在浏览器，不发送给底图服务。地图不显示极区或跨日期变更线的轨迹段。具名个人展示原有完整展示规则不受此接口过滤规则改变。

## 同批次的界面修复

- **开关悬停时背后的一圈**：全局的“按钮悬停玻璃填充”规则优先级高于开关自己的“去背景”规则，悬停时把整个 64×44 的按钮框填成灰色，露在 28 高的轨道上下；该悬停规则现在排除 `.rn-switch`（设置页、用户管理的开关都受益）。开关玻璃层的底色改为可由行设置（`--switch-ground`），用户管理悬停行用与行相同的颜色。
- **最近动态的日期列**：放在面板（`.aux-panel`）里时，日期列遮线的底色改为面板底色（`--timeline-ground`），不再露出一块灰。
- **测试**：`footprint-card-deck` 的返回地址断言允许 `?id=`。
