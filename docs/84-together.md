# 一起跑步

## 使用方式

「一起跑步」只有一个开关：管理员在用户管理中的开关与用户在设置中的「加入一起跑步」读写同一个值（见文末“单一开关与不再按记录可见性过滤”），另须开启「公开个人主页」。普通账号还须启用并开启个人展示；站主沿用现有站主展示规则。访客可从导航进入 `/together`，查看所选周期总里程、参与人数和次数，切换周/月/年排行，在地图下方图例筛选参与者，或通过动态进入记录。最近动态复用跑步记录的时间线样式（面板里日期列的底色与面板一致，不再露出一块灰），手机图例可横向滚动。设置保存只提交有变化的字段。

动态城市由浏览器根据返回的简化轨迹和本地城市边界估算，轨迹不可用、未覆盖或识别失败时显示「未识别城市」；地图最多提供最近 500 段轨迹，因此部分动态可能没有可供识别的轨迹。轨迹只做约 0.5 米的容差简化（`ST_SimplifyPreserveTopology(geom, 0.000005)`，度），低于普通 GPS 误差，主要去掉重复和原地不动的点；最初是约 11 米，跑道或操场这类小圈会被削成多边形。合成数据上，跑道圈保留约 86% 的点、5 公里公路跑保留约 79%。预期只有两三人参与、每月不超过百条，所以牺牲体积换精度；最多 500 段时响应约为原来的数倍，若以后参与者变多需要重新评估上限或容差。配速缺失时显示 `—`。

## 接口与隐私

`GET /api/v1/together?period=week|month|year` 无需登录，默认 `week`，无效值返回 422，账号须同时满足一起跑步开关和公开主页，且具名展示可访问；任一条件关闭后下一次请求不再包含该用户。接口不缓存，响应带 `Cache-Control: no-store`。汇总、排行、动态和路线包含参与者的全部记录，不再按单条记录的 `visibility` 过滤（见文末）或地图。总里程、次数和路线按所选周期筛选：以服务端时钟转换到 Asia/Shanghai 的日期计算，自自然周周一、月初或元旦 00:00 起至明日 00:00（不含）；参与人数为符合条件的账号数。最近动态首页为最新 20 条公开记录，不随周期变化，切换周期时重新读取首页；可以加载更多。每个周期地图最多返回最近 500 段路线，超出时显示「仅显示最近 500 条轨迹」。

首页响应新增 `next_cursor`（没有下一页时为 null）和 `tracks_truncated`（确有超过 500 段符合条件时为 true）。`GET /api/v1/together/feed?before=<cursor>&limit=20` 单独读取动态，不重新加载地图或排行；limit 范围 1–50，游标不合法或 limit 越界返回 422。记录以日期和 ID 降序排列，相同日期按 ID 排序，客户端应将游标视为不透明值；数据可能在分页期间改变，并非快照。接口沿用相同参与条件、公开可见性和 no-store。

响应包含参与者标识、昵称、头像版本、公开运动汇总、最多 20 条动态和最近最多 500 段简化路线；不包含邮箱、备注、原始文件或身心健康数据。地图颜色从用户 ID 稳定派生；轨迹留在浏览器，不发送给底图服务。地图不显示极区或跨日期变更线的轨迹段。具名个人展示原有完整展示规则不受此接口过滤规则改变。

### 手机信息卡避让地图署名（2026-11-03）

手机上地图展开的版权署名可能占两行，原先固定离底 2rem 的信息卡会压住它。`FootprintMap` 用 ResizeObserver 把署名的实际占用高度写入地图框的 `--map-attribution-clearance`，一起跑步页手机宽度（≤640px）下信息卡的底边取 `max(2rem, 署名高度 + 0.5rem)`。新增回归用例“手机信息卡不遮挡地图版权署名”（320/361/390px，署名展开与收起），去掉修复后该用例在 320px 失败。

### 手机底部抽屉与地图尺寸（2026-11-03）

**使用方式**：宽度 ≤959px（上下堆叠布局）时，点击动态不再滚动回地图，而是从底部升起一个抽屉，里面是该记录的路线地图（沿用跑步记录的 `ActivityPreview`/`RouteMap`，路线用跑者颜色）、指标和「查看完整详情 →」。「关闭」按钮、点击遮罩和 Esc 都能关闭，关闭后焦点和滚动位置回到刚才的卡片；页面本身的总览地图只负责筛选跑者，不再显示选中记录的信息卡。≥960px 的桌面布局不变（粘性地图、选中高亮、地图工具栏右侧的详情按钮）。窗口在两种宽度间切换时，抽屉关闭、桌面选中状态清除，不遗留半个状态。

**实现**：`TogetherRecordSheet.svelte` 是页面专用组件（原生 `<dialog>` + `showModal()`，复用全局对话框的滚动锁定和遮罩令牌 `--surface-backdrop`），不是通用 Drawer；设计系统里“暂无通用 Drawer”的结论不变，移动导航仍是文档流。

**地图尺寸修复**：紧凑地图（本页）原先用 JS 按“地图框距视口顶部的距离”算高度，所以同一视口下高度取决于上一次缩放窗口时页面滚到哪里（实测同一 1440×1000 窗口出现 424/534/593）。现在紧凑模式只用 CSS：桌面 `clamp(424px, 100dvh − 13rem, 720px)`，堆叠布局 `45dvh`；不再写内联高度。非紧凑地图（足迹页）仍保持原算法。

**地图信息卡避让署名**：手机不再显示信息卡，避让署名的规则改为对所有宽度生效（窄桌面两列布局里仍可能重叠）；回归用例改在 960/1100/1440px 检查。

**验证**：合成 API 的 `together.spec.ts` 21 项通过，新增“手机抽屉（含 Esc、点遮罩、焦点与滚动恢复、切到桌面自动关闭）”和“桌面与手机来回切换时地图尺寸一致”两个用例；`pnpm check` 0 错误。未在真机上验证。
