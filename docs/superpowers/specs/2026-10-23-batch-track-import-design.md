# 轨迹文件批量导入设计

## 背景与目标

`/activities` 的导入卡片一次只能选一个 GPX/TCX 文件。大量导入（同一种格式、几十到几百个文件）时，用户需要逐个选择、逐个提交，每个文件之后还会重新加载一次活动列表。

目标：让用户一次选择多个同格式文件，由页面依次导入，结束后给出汇总，并且不改变后端接口、响应结构和数据库。

## 已确认的需求

- 典型场景：同一种格式，几十到几百个文件。
- 某个文件失败（重复、格式错误、超时等）时，继续处理其余文件，结束后汇总。
- 不做并发上传、断点续传、文件夹递归选择、逐文件编辑标题或补录日期、GPX 与 TCX 混合批量。

## 方案选择

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A 前端依次排队 | 多选后按顺序逐个调用现有 `gpx-imports` / `tcx-imports` | **采用**：不改接口，沿用导入锁、CSRF、重复检测 |
| B 新增批量接口 | 一次请求带多个文件，后端一把锁处理 | 暂不做：新增公共接口，需重新设计请求体上限与超时，且需要独立测试库验证 |
| C 压缩包上传 | 上传 zip 后端解压 | 不做：需防压缩炸弹，风险和工作量最大 |

后端对每个用户同一时间只允许一个导入（`pg_try_advisory_lock`，冲突返回 429 `IMPORT_BUSY`），所以客户端并发上传没有收益，队列必须串行。若方案 A 上线后仍嫌慢，再在有测试库时评估方案 B。

## 交互设计

- 文件选择框与拖放区允许多选。选择 1 个文件时，行为与现在完全一致，标题、时区、补录日期、TCX 时间解释都可用。
- 选择多个文件时：
  - 格式按扩展名判断，且所有文件必须同一种格式。混入不同扩展名或不支持的扩展名时提示“请分开导入同一种格式的文件”，不开始导入。
  - 标题、补录日期禁用并说明“批量导入时不可用”；时区沿用账户时区；TCX 时间解释使用页面当前选择，对整批生效。
  - 显示“共 N 个文件”和“开始导入”按钮。
- 导入中：显示进度“第 i / N 个”和当前文件名，提供“停止”按钮。停止只是不再发送后面的文件，已完成的保留；正在进行的请求等它结束。
- 批量期间沿用 `controlsBusy` 互斥：导入控件、编辑、删除、小米导入均不可操作。
- 完成或停止后显示汇总：成功 X、重复跳过 Y、失败 Z、未处理 W（仅停止时）。失败项列出文件名与中文原因，并提供“重试失败项”（只重试失败，不含重复）。导入警告（如缺少时间）只显示合计数量，不逐文件展开。
- 沿用现有导入卡片的样式、语义令牌与反馈组件；不新增通用组件，不全局换肤。

## 队列逻辑

新增纯逻辑模块 `frontend/src/lib/import-queue.ts`（可在 Vitest 中单测），页面负责界面与副作用，队列只依赖一个“导入单个文件”的函数和中止信号。

- 严格串行，一次一个请求；每个文件前仍通过现有 `uploadGpx` / `uploadTcx` 取新的 CSRF。
- 单个文件的结果分为：成功、重复（409 `*_DUPLICATE`，视为已导入而跳过）、失败、未处理。
- 429 `IMPORT_BUSY`：按 `Retry-After`（缺失则 1 秒）等待后重试，同一文件最多重试 5 次；仍失败计为失败。
- 401：立即停止整个队列，清除私人状态并跳转登录，与现有约定一致。
- 前端先拦截超过 10 MiB 的文件，直接计为失败，不发送请求。
- 保留 `disposed` 标志与单调令牌：页面卸载或新批次开始时，旧队列停止，不再更新状态。
- 队列期间不重新加载列表，也不触发 `runnote-activities-changed`；结束（含停止）后各触发一次。

## 接口与隐私

- 后端接口、响应结构、数据库均不变。导入仍经 SSR 代理的既有上传白名单，请求头白名单与 11 MiB 上限不变。
- 文件名只显示在本页内存状态中，不写入本机存储，不发往除既有导入接口以外的任何地址。
- 后端每个文件仍会提交一次数据版本更新；足迹 worker 会把 1 秒内连续的唤醒合并为一次扫描，不会每个文件重建一遍快照。

## 错误处理

| 情形 | 行为 |
| --- | --- |
| 409 重复 | 计入“重复跳过”，继续 |
| 413 / 422 / 400 / 503 / 超时 | 计入失败，记录文件名与中文原因，继续 |
| 429 `IMPORT_BUSY` | 等待后重试，超过次数计入失败 |
| 401 | 停止队列，清除状态，跳转登录 |
| 网络中断 | 当前文件计入失败，继续下一个 |
| 页面卸载 | 队列停止，不再更新状态 |

## 测试计划

- Vitest `tests/unit/import-queue.test.ts`：全部成功；含重复；含失败；429 重试后成功与重试耗尽；401 立即停止；停止后剩余文件为“未处理”；超过 10 MiB 不发送请求；混合格式被拒绝；卸载后不再回调；重试失败项只处理失败项。
- Playwright（合成 API，需在 `frontend/tests/fixtures/ui-api.mjs` 或该 spec 的 `page.route()` 中补齐）：多选导入进度与汇总；重复与失败的汇总及“重试失败项”；停止；单文件流程不变；移动端无横向溢出；键盘与可见焦点；批量期间其他控件不可用。
- `pnpm check`、`pnpm test`、相关 Playwright 配置。验证主题、响应式、加载/成功/错误状态。

## 范围与风险

- 仅改前端：`routes/activities/+page.svelte`、新增 `lib/import-queue.ts`、测试与合成 API。不改后端。
- 风险：数百个文件串行仍然受每文件约百毫秒到数百毫秒的后端耗时限制，总时长是线性的；若不满足，需要方案 B。
- 页面文件当前已较大，导入相关状态应尽量收在队列模块和一个小的展示片段中，避免继续膨胀；不顺手重构无关部分。
