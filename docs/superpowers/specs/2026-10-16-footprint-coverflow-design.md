# 足迹卡片双侧 3D 堆叠设计

## 范围与复用

只升级活动详情“本次足迹卡片”的右侧排列和交互。复用 `WallCard` 的原生按钮、白色/系统主题表面、绿色强调、路线预览、文字、边框、圆角和阴影；保留左侧介绍、链接、父布局和详情切换回调。保持当前卡片基础宽度 9rem，不添加依赖，不应用玻璃材质或其他视觉风格。

当前分页缓存、日期/UUID 倒序定位、完整记录切换、URL 替换、来源返回、错误重试和 401 清理继续沿用。此设计不改后端、接口、数据库或运动指标。

## 空间布局

当前记录在右侧视口中央，大小为原卡片大小，深度 0、最高层级。其他真实记录按相对索引排在两侧，每侧最多四张，按距离逐级缩小、沿 Y 轴向中央旋转并向后平移。用容器实测宽度计算侧卡数量和横向步幅，避免侵入介绍区与两端箭头。

从新到旧保持左到右。到序列首尾时对应侧留空，主卡片仍居中，不复制记录或循环。小容器减少侧卡，极窄手机仅显示中央卡片；手机降低旋转和深度。卡片保持内容驱动的自然高度，预留倾斜和阴影空间。

## 动画与交互

`coverflow.ts` 封装纯位置计算、DOM action 和导航输入。复用项目既有标量弹簧，只使用其运动计算，不加载玻璃材质。所有位置来自同一个连续的当前索引，成功选择后重定向弹簧目标；动画期间不锁操作，新的选择接续当前速度与位置。网络请求仍沿用单次在途保护，读取失败保留当前内容。

分页读取包含一张不可见缓冲卡；移动过程中临时保留旧窗口 DOM，离开卡片在真实轨迹上淡出，弹簧结束后清理。按连续距离计算空间层级，在中点交换前后关系，避免重新排序闪烁。

中央卡片使用 `card-tilt.ts` 的原生事件和动画帧，扩展为双轴弹簧跟随、轻微白色高光和小幅路线/文字视差。最大倾斜 6°，路线位移不超过 2px、文字位移更小；保持原排版与内边距。指针移动只写当前 DOM 的 CSS 变量，不触发 Svelte 页面响应式更新。侧卡不启用倾斜/高光。离开平滑恢复，减少动态效果、触屏或卸载立即清理。

点击任意可见侧卡，调用已有完整记录切换并移动至中央。左右箭头保留；焦点在区域内时方向键切换，卡片上的键盘焦点转移至新中央卡片，箭头保留自身焦点。触屏在卡片区域横滑切换，纵向滚动正常，滑动后抑制误点击。所有输入有界，无动画队列。

## 可访问性与生命周期

原生按钮和中文 aria-label 保留，中央 aria-pressed，读屏状态说明当前记录。不可见缓冲/离开卡片 inert 且 aria-hidden，不抢占焦点。原生按钮保留可见焦点边框。减少动态效果时跳到目标位置，取消倾斜、高光、视差与弹簧动画；仍可用箭头、键盘和触摸。

action 卸载时停止弹簧、清理 MutationObserver、事件和 pointer capture；组件继续清理 ResizeObserver、媒体订阅、缓存与请求令牌。

## 验证

先以真实 Chrome 复现平面布局不符合 3D 需求，再验证中央对齐、镜像旋转、深度缩放、内容与原有材质、侧卡点击、快速连续切换、分页缓存、首尾、键盘焦点、触摸横滑/纵向滚动、减少动态效果与卸载。使用合成 API，桌面与 320/390px 实际截图检查。运行最小单元/专项 UI，再相关回归、pnpm check、pnpm test、pnpm build 与 diff 检查。区分合成 UI 和真实后端验收，保留其他工作区改动，不提交。

## 后续增量：点击懒加载与九卡

按用户追加要求，宽屏由最多 7 张增至 9 张（两侧各增加一张），尺寸、样式与移动端限制不变。详情卡片未选中时不主动读取路线；选择后读取目标详情并提交卡片/指标/URL，路线再独立异步加载。保留路线 token、401、重试与来源返回，路线未完成时仍能继续切换。普通足迹墙沿用原有进入视口加载，不全局改变缩略图行为。

## 懒加载范围修正

用户明确指出侧卡不能都显示“选择后加载”。取消详情卡片的 deferred 限制，恢复既有进入视口时绘制路线缩略图的行为（含相邻缓冲），保持有界窗口；完整详情与大路线继续在选择后独立读取，保留九卡和原有设计。
# 增量：有界滑动浏览

沿用现有双侧堆叠、自动路线预览和整条记录切换。新增桌面主键拖动与触控板横滑；每个手势最多切换一条，纵向滚动及首尾边界保留。横滑惯性在 180ms 无事件后才视为新手势，反向输入允许立即返回。列表每次最多读取 20 条，LRU 只保留 3 页（最多 60 条摘要）；可见窗口最多 9 张，加前后各 1 张不可见缓冲。读取窗口直接使用本次返回页，避免并行装配依赖已被淘汰的缓存。动画保留实际可见位置、上一目标和新窗口之间已经读取的路径卡片，避免快速跨卡时中间缺卡；结束后回到最多 11 张挂载卡片。路线预览限于挂载窗口，不缓存全历史；列表上限不是 SQL 查询条数上限。


## 修正：滑动只浏览

滑动浏览与记录选择分离：手势（鼠标拖动、触屏、横向 wheel）仅改变浏览中心，不调用详情切换、不更新 URL/指标/大地图。点击卡片或两侧按钮才选择记录；方向键浏览并把焦点移到新中央按钮，Enter/Space 确认。浏览中心独立于 selectedIndex，中心卡拥有倾斜反馈，aria-pressed 仍表示真实当前记录。按钮相对正在浏览的中央位置选择前后记录。浏览继续沿用20条/3页缓存、请求令牌和鉴权保护，错误重试保留浏览/选择意图。

## 追加要求：统一尺寸、持续浏览

全部卡片保持相同投影宽高，不再按距离缩放、旋转或向后移动；保留白绿内容、圆角、边框、阴影、叠放、索引弹簧及中央指针倾斜。根据容器减少侧卡，保证相邻卡中心可点击；宽屏仍最多9张。手机只有一张可见时仍保留完整卡宽的位移，使横滑有真实水平运动。

横向wheel每累计48px继续推进，不再一整个手势仅移动一次；单事件最多4格，长拖动每80px计一格、最多4格。组件把单次及在途目标限制在当前浏览位置前后max(2, radius)格，读取列表时合并成最新意图并串行继续，防止丢失操作或并发洪泛。列表仍每批20条、缓存3页60条，可持续浏览全部历史，只有真实首尾是边界。手势与方向键只浏览；卡片点击、箭头、Enter/Space确认按钮才切换详情。
