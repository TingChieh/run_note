# Mi Fitness 跑步数据恢复与设备字段补充设计

状态：用户已确认；代码与隔离测试完成，结果见 `docs/42-mifitness-import.md`。后续开发库迁移已另行授权并完成，见 `docs/43-mifitness-development-migration.md`；真实数据未入库。

## 目标与范围

恢复用户导出中的跑步记录，并补充确有数据、含义明确的设备指标。首期仅处理跑步，不建立通用健康数据中心，不导入日常心率、睡眠、血氧、压力、体重、步行或骑行。真实数据留在仓库外，不作为测试夹具。

已获取 162 份跑步 GPX 原件；另有 5 次跑步只有设备汇总。设备汇总共 167 条。下载成功不代表已入库。

## 现场证据

- 162 份原件共 213,945 个点、162 个源段，均只有坐标和时间，没有海拔、逐点心率或逐点步频。
- 原件均声明 GPX 1.1，但 XML 根及子元素没有 GPX 命名空间；现有 `parse_gpx` 对 162 份原件均返回 `GPX_XML_INVALID`。
- 只在派生副本中补充标准 GPX 1.1 命名空间后，现有解析器成功解析 162 份，时间完整，非法坐标为 0，规范哈希共 162 个且互不重复。规范化前后所有元素属性值与文本值逐项相同。
- 首条下载 GPX 的 UTC 时间与导出汇总开始时间仅差 1 秒；全批首点与设备开始时间之差为 0 至 815 秒。不得对本批文件统一减去 8 小时。已有 TCX 样本的时间解释规则继续有效。
- 一条最大步频值为 5730，需要作为无效指标告警；一条设备用时超过设备开始与结束之差，需要保留质量提示。
- 海拔全为占位值，爬升和下降为 0 或 -1，跑力及落地指标为 0；不为这些占位数据新增可展示字段。
- 步幅和恢复时间的来源单位没有在导出说明中明确，不把推测的厘米或小时写成权威字段。

## 方案比较

1. **推荐：原生 Mi Fitness 单次导入 + 跑步设备指标扩展。** 162 次合并设备汇总与轨迹，5 次支持无轨迹汇总；来源和重复判断可追溯，新增一条独立导入入口。
2. 转换 TCX 后使用现有入口。改动较小，但需要约定扩展字段，且现有 TCX 必须有 GPS，无法承接 5 次汇总记录。
3. 建立完整健康数据中心。可承接大量健康采样，但涉及另一套数据模型、统计与隐私界面，超出本次跑步恢复的必要范围。

## 复用字段与新增字段

距离、设备用时、经过时间、平均配速、热量、步数、平均心率、开始与结束时间、日期及账户时区沿用现有字段，不重复建列。

活动表新增以下 8 个可空字段。旧记录保持 NULL；不通过历史轨迹推算或回填。

| 字段 | 含义与来源 | 校验与使用 |
| --- | --- | --- |
| `max_heart_rate_bpm` | 最高心率，`max_hrm` | 整数 1–300；来源 0 视为缺失 |
| `min_heart_rate_bpm` | 最低心率，`min_hrm` | 整数 1–300；来源 0 视为缺失 |
| `avg_cadence_spm` | 平均步频，`avg_cadence` | 数值大于 0、不超过 400，步/分钟 |
| `max_cadence_spm` | 最大步频，`max_cadence` | 数值大于 0、不超过 400，步/分钟；5730 不写入 |
| `vo2_max_ml_kg_min` | 设备估计最大摄氧量，`vo2_max` | 有限正数、不超过 150；仅作设备估计展示 |
| `training_load` | 小米训练负荷，`train_load` | 有限非负数、小于 10^9；不混作通用跨设备评分 |
| `aerobic_training_effect` | 小米有氧训练效果，`train_effect` | 有限数值 0–5；0 是有效值 |
| `anaerobic_training_effect` | 小米无氧训练效果，`anaerobic_train_effect` | 有限数值 0–5；0 是有效值 |

新增指标缺失或异常时只留空并列出具体指标质量提示，不丢弃整次跑步；基础距离、时长等必要字段非法则拒绝该记录。若最高与最低心率或平均与最大步频矛盾，该组指标留空并告警。保留受限来源摘要用于核对，不用静默修正掩盖来源异常。

步幅与恢复时间只保留在来源摘要中，标记单位未核实，不进入带单位的展示字段；后续取得来源单位证据后再扩展。

## 导入与持久化

- 在活动来源约束中增加 `mifitness`，新增 `mifitness_imports` 来源表，遵循现有用户归属、级联删除及来源归属复合外键模式。
- 来源表保存受限设备汇总、解析版本、来源记录指纹、可空原始 GPX 字节与原文/规范哈希。不保存原始整份 CSV、签名下载 URL、账号或设备 ID。新增指标为私人数据。
- 手写下一条线性迁移；现场已有迁移至 `0008_activity_labels`，实施前重新确认序号。只在受保护的独立 `_test` 库验证，不执行开发库迁移。
- 新增 `/api/v1/mifitness-imports`，一次处理一条设备汇总与可选单个 GPX。使用 JSON 表单字段（至多 4096 字节）承接严格白名单输入，不让服务器根据用户传入 URL 下载文件。
- 单文件仍不超过 10 MiB，请求仍受 SSR 11 MiB 上限保护；不上传整份 439 MB 数据，不放宽 SSR 转发头或目标源。
- 来源专用解析器仅为已经识别的无命名空间 GPX 1.1 构造安全内部树；保存下载原文，复用现有 GPX 点、段、空间计算及安全限制。不扩大普通 GPX 解析器的输入约定。
- 有轨迹时保留轨迹点 UTC 原义，以设备距离和设备用时计算配速；设备开始和结束可早于或晚于轨迹首末点，分别记录，不强制首点等于设备开始。
- 无轨迹时按设备开始和结束建立活动，`has_route=false`，不生成坐标和地图。完整设备时间为 `temporal_quality=complete`，同时记录其时间来源为设备汇总；设备用时和经过时间继续分开。
- 不把设备用时与经过时间的差值直接命名为暂停。设备用时大于经过时间时提示来源不一致，不篡改原值。
- 复用现有每用户单导入 advisory lock、身份二次校验、`lock_owner`、版本递增、原子事务与 owner 范围查询；不新增第二套锁。
- 同用户来源指纹及跨格式规范轨迹哈希用于防重。时间/距离近似相同但哈希不同只作疑似重复提示，不自动合并或覆盖。已存在记录返回本人活动链接；补齐已有记录的缺失指标须有明确选择，不默认覆盖任何非空值。补缺仅处理上述 8 个新增指标及已有热量、步数、平均心率；不修改已有距离、设备用时、经过时间、配速或轨迹。补入指标对应的白名单来源值同步保存。
- 日期使用绝对时间与所选 IANA 时区转换，默认账户时区。导出中的 `timezone=32` 不直接当作 IANA 名称或小时数。

## 页面与私有接口

- 私人活动响应与前端运行时校验增加上述可空字段，列表、活动详情及数据汇总中的活动详情使用一致的指标展示。
- 新指标在私人详情的“设备指标”区域展示，有值才展示；来源和异常提示用中文。沿用现有令牌与组件，不重构页面布局。
- 活动页增加 Mi Fitness 导入入口，读取本机已整理的白名单汇总与匹配文件，逐条提交；显示成功、重复、失败、仅汇总的状态。批次中单条失败不影响已完成条目；同一用户仍串行请求。
- 提交前显示设备指标、时间解释、轨迹有无和异常值预览；匹配关系冲突时拒绝猜测。
- 公开活动、分享响应和 AI 供应商请求继续使用现有白名单，不自动增加这些设备指标、来源摘要或坐标。
- 保留 401 清理、请求令牌及卸载防护；新增 UI 接口必须在合成 API 中补齐。
