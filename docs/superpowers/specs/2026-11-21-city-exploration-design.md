## 1. 三种方案

| 方案 | 交付 | 误差与成本 |
| --- | --- | --- |
| A · 复用全球命中列表 | 按已有城市命中列表展示记录数、最早关联日期和网格概览。列表用“关联活动”措辞 | 最快，按活动与城市命中边实时聚合。点城匹配是近似值，整段距离在跨城时会重复，无法提供可相加的城市累计跑量 |
| **B · 城市边界与首次格网（推荐）** | 本人城市图鉴、城市详情、边界内累计跑量、首次跑步记录、年度热图、每月覆盖趋势。仅有城市点时显示“附近有记录”；有轨迹的账户始终可看全域格网 | 复用足迹缓存、离线 atlas 与 PostgreSQL/PostGIS；增加有界的服务端空间计算和 SQL 聚合。首版可零迁移，精确城市统计局限于现有城市面。街道延后 |
| C · 本地步行路网匹配 | 在路网覆盖充分的试点城市展示高置信度的已跑路段 | 需要新的路网数据、许可审查、离线构图与更新、匹配/质检、后台重算和缓存。当前不具备交付条件 |

MVP 包含 B 中的图鉴、已观测格网和首次探索。成就由当前活动数据推导，表现为“首次跑过某城”和“本期新增 N 格”，不发永久徽章或通知。后续可扩展有出处的城市边界、较大数据集的派生索引，以及经验证的路网试点。

## 3. 产品与统计口径

### 城市、首次和累计

- **活动范围**。与现有运动足迹使用一致的本人活动和轨迹范围，纳入全部可见性。无轨迹的手录或导入活动可进入全站跑量，但在图鉴只计“无轨迹”，无城市、格网和首次。跳过空边或不支持的格网纬度，并单列质量计数。仅单点与边界擦过可贡献原有格网命中，城市首跑要求至少存在正长度且可归属的轨迹。
- **有边界的城市**。用当前 atlas 市级多边形与原始有序轨迹段求交，以活动内有效边的地理长度为分母。使用 bbox、按活动独立查找候选、复用 atlas 版本和 geometries；缓存命中数组可作为线索，正长裁切仍须校验，简化线和候选缓存不能作为最终分配的权威。沿线分割保持重复跑的长度，不跨丢失轨迹段接线；公共边、重叠面或无覆盖的线段归“未分配”。各城市份额互斥，日期变更与裁切无关。
- **累计跑量**。对每条活动，将服务端 `distance_m` 乘以 `某城市内有效边长 / 活动有效边总长`。无可用分母留未分配；显示值是跑量分摊估计，特别是运动设备里程和轨迹长度有差异时。跨城活动可计入各有正长的城市各一次，各城次数不可直接相加为活动数。距离在聚合后才舍入。例：10 km 活动的有效轨迹分别有 20%、70%、10% 在 A 城、B 城及未知区，则分配 2、7、1 km。图鉴的“城市边界内累计跑量”只加总确有边界归属的份额。
- **首次跑步记录**。对正长命中取现存活动 `MIN(activity_date)`。沿用记录保存的运动日期与时区，不用上传时间、浏览器时区或到达城市的逐点时刻。跨午夜活动仍使用同一活动日期。首次信息指首条可归属的跑步记录，无法证明用户实际首次到访。日期与累计跑量默认为全部历史，切换年份只改变地图和趋势；图鉴的“本年首次跑过”取各城全量首日再按当年统计。
- **仅城市点**。用全球 atlas 已缓存点城做“附近有记录”，标明“首次匹配到附近轨迹”，分别以活动日期取最早值；同一活动可匹配多个点。未知位置留“未归入城市”，不按标题、用户所在地、首点或最大城市自动指派。点城市的边界内跑量和城市覆盖显示为空；全域格网仍然可用。一级行政区覆盖依格网中心与离线一级行政区边界归属，城市点不会改变该归属。

### 新探索与趋势

- **格网身份与归属**。一格是 `(i, j, grid_algorithm_version)`。全球去重；区域内用格网中心与 atlas 面相交归一个城市与一个一级行政区，边界同级冲突用稳定代码排序，否则留为未知。附近城市点不参与格网归属。100 m 格网含相邻边界接触和孤立点，足迹图的网格口径与里程裁切口径各自可复核；极短跨城片段因此可能有里程、无城内中心格。
- **首次与新格**。对每格从全部现存历史活动取最早 `activity_date`，按该日期所属月份统计新增格。选定年份前已出现、当年再次经过的格只增加热度。某格同日被多条活动命中仍只新增一次。导入旧活动可能把首次从今年移动到过去，删除最早活动会回到下一次命中，删除唯一命中则移除格网和相应成就。老账户冷填充时显示“正在整理历史足迹”，完整性未知时不把缺失年份视为零。
- **覆盖指标**。全域、一级行政区、面城市三种范围共用定义。月度新增为当月首见格数；累计为之前已见格数加上当月新增；年度热图每格为所选年不同活动的命中数，可切换仅显示年度新增。未来月份显示 `—`，通过含 0 的实际月份保留时间连续性。进行中年份写“截至当前累计”。MVP 用格数比较覆盖，不估算全城跑完比例、可跑面积或街道公里。
- **变更回算**。每次读以本人当前活动 join 派生行，距离及日期直接取活动记录。删除单条及批量删除后按当前 owner 数据重新聚合；不保留已删除活动的旧成就。元数据编辑只触发读结果失效，避免重算不变的空间中间结果。将来开放轨迹替换时需要明确使每活动的格网、atlas 命中及裁切衍生结果失效，不能只增用户版本而复用旧几何。atlas 更新可能修正历史归属，旧版本与新版本不混算，保留匹配算法版本供支持诊断。

## 4. 街道匹配可行性

100 m 格网只能证明一项活动的轨迹与投影格相交。城市里平行街道、街口、高架、绿道、私有路与定位漂移会同时落在一格，格内缺失经过的方向和线形。现有 OpenFreeMap 样式与视口瓦片供绘图，`place_titles` 地物只用于命名；两者均未提供可用的步行拓扑和路段遍历证据。MVP 将此需求降级为“覆盖热图”和“新增格网”，用命中活动数表达反复到访。

后续可行的试点是固定住一份 OSM 区域 PBF 版本，候选取得方式为 Geofabrik 区域提取。离线以步行准入构图（`highway`、`foot`、`access`、`bridge`、`tunnel`、`layer` 等），在本地服务用原始有序点、段间断裂及可用 GPS 精度进行序列匹配；OSRM Match 是需验证步行 profile 和结果的候选。按路网版本保存路段 ID 和部分经过比例，仅把实际经过且达质检门槛的路段渲染成已跑。对离线断点、GPS 断裂、无名路、封闭道路、交叉高架、并行道路、越野以及匹配不确定性继续回落格网。路网按发布快照离线更新，可校验或回退；匹配前后均禁止把私人轨迹交给第三方路由或地图匹配服务。

抽样覆盖要按目标城市分层检查步道完整性、路段命名、误匹配、高架并行召回率、覆盖率和重匹配时延。建议试点先冻结单个区域和快照，验证路段的精确率与未匹配比例，并测构图库盘占用、内存、单位 GPS 点耗时、持续导入和全历史重算。评估 ODbL 归属、离线图上的署名、修改路网或对外提供派生数据库时的适用条款；需要发布版本与归属记录。参考 [OSM 版权及许可](https://www.openstreetmap.org/copyright)、[Geofabrik 区域提取](https://download.geofabrik.de/)、[OSRM Match 接口](https://project-osrm.org/docs/v5.24.0/api/#match-service)。

## 5. 界面与隐私

- **入口**。在既有“运动足迹”页头加本人子入口“城市探索”，普通用户通过本人 workspace，站主通过确认登录身份的根足迹进入。独立本人子页面承载目录和详情，列表/城市、范围和年份留可回退状态。保留原有全量地图和模式。具名展示无入口，即使登录用户刚好在访问自己的具名展示。入口授权由服务端复核；新接口固定使用 session owner，拒绝外部 owner/username，并经 SvelteKit 同源 SSR 代理传递。未知代码及不属于当前账户的城市详情返回 404。
- **图鉴**。先列边界内有跑步记录的城市，按最近活动日期及稳定代码排序，显示所属区域、活动次数、累计与首日；次区显示附近城市点和未归入城市的计数。无活动显示“还没有跑步记录”，有活动无轨迹显示“暂无带轨迹的活动”；只有点时仍可从图鉴打开全域和一级行政区的格网视图。第一年、同名城市、未知地点都有明确标签。
- **详情**。顶栏保留两项全量指标与年度新增；地图提供覆盖热图和新增格网切换，以色阶表达热度，以明确描边与图例表达首见，月份图给出新增和累计表。可选全域、一级行政区与边界城市；最细局部地图不可用时可读统计，关闭底图仍可看本地图层。地图网格点击、图表悬停可定位信息，键盘通过现有焦点模式、区域标签和完整表格获取等价内容。
- **响应式与状态**。桌面地图和趋势并排、图鉴和附近列表并排，平板在空间不足时转纵排，手机先选城市/范围或年份，再读指标、地图和趋势。沿用 PageHeader、PageSkeleton、FeedbackState、语义令牌、44px 操作目标、可见焦点、读屏公告及 reduced-motion。初次加载用同尺寸骨架；读到当前版本的旧请求结果时可呈现已加载区域，标明后台整理进度。活动版本变化（特别是删除）、身份变化和 401 要清除旧私人数据；同一版本的可重试失败不遮挡其余成功区块。无匹配和未就绪分别显示，精确数据请求超预算时提示缩小地图视口或等待后台整理。
- **位置保护**。新接口、代理、Etag/缓存键、浏览器状态及日志按本人隔离；私人响应 `Cache-Control: private, no-store`，进程内派生缓存钥匙包含 owner，浏览器中不持久化 GeoJSON、格网或统计结果。分享摘要、公开 API、主页、AI 输入与第三方请求不添加这些数据；地图 URL、分析事件与日志禁止写格网、精确位置和首跑数据。若启用外部底图只用 BasemapPicker 已允许的样式和瓦片资源；由于视口瓦片可透露关注区域，城市探索默认先绘本地底图，外部底图需在这一视图明确选择，且不能把地图偏好解释为准许外发轨迹。

## 6. 数据、接口与预算

### 读取模型

1. **列表先行**。聚合从有索引的本人活动、当前 `ActivityGlobalFootprintCache` 和内存版本化 atlas 开始。专门用 SQL 分组统计活动日期与计数；城市点可基于数组直接聚合。城市面累计跑量需要新的正长裁切。优先用有界的实时查询计算份额，常见账户可直接按当前活动回算。保持只读，给空间查询设置语句和请求截止，减少认证共享锁的持有时间；只在数据版本一致且完整时发布统计。
2. **趋势按需**。从当前版本的 `FootprintActivityCache.cells` 提取键，join `activities` 取日期，对目标范围运行一次 `GROUP BY (i,j), MIN(activity_date)`，再分桶并计算窗口累计。“新”不受查询日期过滤影响，热度只计所选年。对全部活动预检查缓存覆盖；区分已完成但无格、尚未构建和失败缓存，避免只聚合已填充数据就宣布历史已完整。按活动数、JSONB 解包的格网命中量和查询时间限制成本。对无可用快照的大账户，列表与范围聚合可独立显示；仅当后台或有界范围可证明完整时展示相应统计。
3. **地图单独请求**。列表请求只返回数字和命名元数据，选中城市后再请求对应视口和年份。后端用格网索引重建多边形，低缩放可用对齐 4×4、16×16 等块汇聚当前视口，明确传回展示粒度与图例；重聚合只改绘图，不改 100 m 指标。低缩放只可汇总格数，跨格活动次数不得直接相加后沿用热度图例。使用现有 MapLibre 本地源、`setData`、`BasemapPicker`、控制器与 `watchSystemTheme`，按 `moveend` 和防抖更新 bbox，废弃旧请求，保护相机与焦点；不要把每格生成 DOM 节点。曲线或柱形的序列最多 12 月，表格共享服务端数据。
4. **读缓存按证据加**。先做查询计划和合成基准。若热请求有收益，按 `owner + activity_data_version + atlas_version + grid_version + rules_version + range/year/viewport` 做有界进程内缓存与同键合并；过滤参数做规范化，视口键用格网/瓦片量化避免随拖动无界增长。若多个端点读取期间版本变化，客户端不混用不同版本，服务端最后发布前校验。缓存失效后的同日回算是正常行为。

### 拟议 API

| 本人读取 | 核心返回值 |
| --- | --- |
| `GET /api/v1/me/footprints/exploration/cities?limit=&offset=` | `items,total,limit,offset`，返回城市代码、边界类型、区域名、首日/末日、相关活动数、可归属米数或 null；补充图鉴总计和未知原因计数，汇总先于分页 |
| `GET /api/v1/me/footprints/exploration/{scope}/{code}?year=` | `scope=global|region|city`，全域约定固定代码；返回累计与首日（城市）、到期格网数、本年新增、逐月新增和累计、源版本、atlas 版本、整理状态；点城只提供匹配日期和活动数 |
| `GET /api/v1/me/footprints/exploration/{scope}/{code}/cells?year=&bbox=&zoom=&layer=` | 仅授权视口内的数据与有效粒度，格或块的键、范围、热度或新增量、显示是否聚合及源版本；不将活动明细和原始轨迹混入 payload |

API 保留项目响应信封、后端权威范围校验、可机读错误码和生成式契约，前端做运行时字段校验。bbox 校验经纬度、最大范围、换日线和最大输出格；选择过宽时返回聚合结果或清晰的缩小视口反馈。整理状态区分 ready/pending/failed，未完成统计用 null 和覆盖计数。列表和趋势响应无精确坐标。显示地图所需的格网位置只从格网读取端点取得。

### 迁移与容量门槛

| 条件 | 处理 |
| --- | --- |
| MVP 的实时查询和现成缓存满足门槛 | 零迁移。复用现有版本、owner 日期索引、每活动缓存和后台补建机制，只新增本人查询与 UI。全量快照只做已有用途，不向其塞时间序列，也不在活动写入路径维护城市汇总。 |
| 格网 JSONB 解包和重复扫描超预算 | 先验证裁切/聚合请求解耦与进程缓存效果。持续超预算再提议手写迁移，候选为可回填的每活动网格键或带范围归属的派生行，按 `owner, scope, i, j, activity_id` 检索，日期仍与现存活动 join。按账户幂等回填、可恢复重建，标记版本与完整性，启用前验证新旧口径。代价是每次活动×命中格的存储、索引和写放大；实际空间预算需测。 |
| 城市几何裁切成为主要瓶颈 | 优先物化版本化 atlas 地理索引或后台缓存每活动与城市代码的比例、未分配比例及匹配版本。FK 跟随活动删除，写入仍只记原活动；worker 异步生成派生数据。局部重试要避免坏活动长期占满队列，缓存更新发布前校验活动及 atlas 版本。 |

容量估算按 **每活动去重格的总和**，与全局唯一格不同。3,000 条活动每条 150 格约 45 万行候选，20,000 条每条 200 格约 400 万；这些是合成负载设定。冷热分测 300/3,000/20,000 活动，覆盖重合密集、轨迹分散、跨界长线、单条超时、atlas 更新、旧活动补录及并发 1/5/10 本人查询。记录缓存命中率、未处理行、P50/P95、SQL EXPLAIN (ANALYZE, BUFFERS)、解包行数、临时文件、序列化和 MapLibre 首绘。提议门槛为暖请求城市列表 P95 ≤300 ms、趋势 ≤700 ms、单次地图压缩响应 ≤256 KiB 与 ≤5,000 可见要素，冷路径超过 2 秒预算给局部待整理状态，避免排队拖慢现有足迹。数值需由独立 PostGIS 测试库和目标手机校准。

## 7. 确认项与验证

1. 负责人确认城市面优先、城市点只显示附近记录的首版范围。主要风险是 33 个一级行政区之外缺乏市级累计跑量；若必须覆盖更多地区，先选数据源、校验边界与许可并给出地区优先级。
2. 确认采用权威活动距离按城市边界内比例分配、以及“首次跑步记录”的日期文案。跨城、线段重复、公共边、缺轨迹、轨迹过短、±180°、近极地、历史导入、删除和重新计算都要有合成回归。验证城市合计与未分配米数守恒、月份新增可累加、同格同日只出现一次。
3. 确认以格网作为首版探索成就、全域及一级行政区可降级、外部底图在探索页按需开启。后续街道试点需确定覆盖地区、开放地图许可与质检阈值。接口验收覆盖匿名 401、跨账号 404、公用代理不转发、旧分享白名单、删除后缓存失效与网络请求无轨迹位置。
4. 确认性能门槛和迁移触发条件。真实 PostGIS 查询计划、账号级城市覆盖率、移动设备地图性能、端到端和生产构建本次均未运行。原型使用 Chrome 的 Playwright 视口验证，和生产地图引擎、主题增强及网络接入没有依赖关系。
