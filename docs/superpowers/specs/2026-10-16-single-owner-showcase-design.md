## 现场代码依据

- `frontend/src/hooks.server.ts` 与 `lib/api/auth.ts` 当前保护 dashboard、activities、footprints、settings、ai，匿名访问跳转 `/login`。

- 后端 `api/dependencies.py` 的 `get_identity` 与 `require_write` 当前区分读取认证和 CSRF 写入，没有管理员角色。
- users 模型无需增加角色列：通过服务端配置的唯一账号识别管理员，沿用现有密码、Cookie、会话及限流。
- activities、statistics、footprints、running_goals、ai_reports 各有已有查询逻辑可复用；原分享模块仅提供摘要，不能直接承担本次完整展示。
- README 的生产拓扑为 Linux 原生 PostgreSQL/PostGIS、Uvicorn、SvelteKit adapter-node、systemd 与 Caddy；部署配置和恢复验证仍处于计划阶段。

## 实现方式比较

| 方式 | 影响 | 结论 |
| --- | --- | --- |
| 独立个人展示读取接口，沿用认证写入接口 | 展示数据与登录身份分开；匿名字段可明确控制；原分享语义可保留 | 推荐 |
| 全面放开既有本人读取接口 | 改动较少，但容易公开账号、分享管理及供应商状态等管理信息 | 不采用 |
| 静态导出展示站并另做管理站 | 需要同步和刷新体系，部署复杂度高 | 当前不采用 |

## 使用方式

### 访客

首页继续进入数据汇总。数据汇总、跑步记录、记录详情、足迹墙、个人足迹与 AI 页面提供只读浏览；导航保留现有主题、材质和响应式结构。目标进度只读显示，AI 页面只展示已完成报告和公开的分析结果，不触发供应商请求。

访客不显示导入、编辑、删除、分享管理、目标修改、AI 生成和账户设置控件。设置属于管理员功能，不作为公开展示页。账户栏展示站主展示名称，不把站主邮箱、用户名或本人登录状态伪装成访客身份。

### 管理员

直接访问 `/admin`：未登录时显示登录表单，登录成功后提供管理入口，可返回原业务页面操作。已有 `/login`、`/register` 页面停止提供登录注册界面；直接调用注册接口同样拒绝。非指定账号不能新建管理员会话，旧的其他账号会话也不得写入或进入管理功能。

“以后只有一个用户”按运行权限解释：系统仅接受配置的唯一账号管理。历史其他账号、记录和关联数据不自动删除，也不归并进站主账号。

## 接口与隐私

新增独立的个人展示 API，查询条件由服务端解析唯一站主账号，不接受访客传入任意 owner、邮箱或用户名切换数据源。公开响应使用独立白名单 Schema，前端接口消费者执行运行时校验。

本次例外允许展示站读取该站主的全部既有和后续运动记录（包括原先标记 private/unlisted 的记录）、指标、目标进度、完整轨迹、精确起终点，以及已完成 AI 报告。该站部署为公开展示站后，原有记录 visibility 不再表示其能阻止站主内容在展示站出现；管理界面的文案必须说明这一点，不能给出错误的隐私承诺。实施前此项随本设计一并确认。

例外只作用于新的个人展示站接口。原 `/u`、`/public`、`/shared` 路径的公开摘要与撤销语义保留；其他账号数据不得进入个人展示响应。

仍不公开邮箱、内部 owner ID、账户设置、自由文本备注、源文件名、原始 GPX/TCX 文件、会话、密码哈希、密钥、供应商错误和管理状态。记录标题、分类、标签及展示名称用于站点呈现。真实轨迹只经同源 API 到浏览器，不加入外部地图 URL；AI 供应商继续只接收既有聚合白名单。

管理员认证沿用既有 Argon2、HttpOnly Cookie、CSRF、来源校验和限流。写权限必须由后端强制执行；不能仅靠隐藏按钮或隐藏登录 URL。

匿名读取不得调用生成报告、导入、更新快照等服务写入路径。足迹的既有生命周期任务可以继续维护站主缓存，公开查询只读取数据及缓存状态。

## 配置与部署

- 在后端集中配置唯一站主/管理员账号，建议字段 `site_owner_email`、环境变量 `SITE_OWNER_EMAIL`。默认值对应本次指定账号；部署者可通过进程环境覆盖，前端不保存或传入身份配置。
- 查询按规范化邮箱精确匹配。账号未找到时返回明确的“展示账号尚未就绪”状态，禁止退回首个用户或任意管理员；不自动注册、创建或重设密码。
- 本次不更改数据库 Schema、不删除历史用户、不修改根 `.env` 或密钥文件。补充 `.env.example` 与部署说明，指定账号须在目标数据库中已存在；空库首次建站的账号初始化属于单独受控操作，不开放公网注册来初始化。
- 沿用原生 Linux + PostgreSQL/PostGIS + Uvicorn + adapter-node + systemd + Caddy，不引入容器。
- `APP_ENV=production`、`SITE_ORIGIN`、`INTERNAL_API_BASE_URL`、认证密钥和 `SITE_OWNER_EMAIL` 的配置须在文档中对应到进程；所有 worker 使用相同配置。`SITE_OWNER_EMAIL` 是服务端身份配置，不是公开个人资料。
- Caddy 直转 `/api/*` 的生产拓扑要求所有访问控制在 FastAPI 同样生效；不能依赖 SvelteKit 路由保护。SSR 代理固定源及七项请求头白名单保持不变。
- 公开响应使用 `no-store`；缓存、搜索索引及 referrer 策略需覆盖新展示路径。关闭注册和限制管理员登录须有直接 API 验证。
- 提供构建产物本机演练和生产部署步骤；不得把本机构建/合成测试通过描述为生产已部署。

实施验收至少覆盖：

1. 匿名浏览全部展示页和直接刷新详情页，展示指定站主数据，不出现登录注册及写入控件。

5. 匿名和非管理员直接请求导入、编辑、删除、目标修改、AI 生成及注册接口均失败；管理员保留 CSRF/Origin 校验。

7. 实际执行相关单测、`pnpm check`、构建、Ruff 和格式检查，并记录实际通过、失败、跳过及未运行项目。
