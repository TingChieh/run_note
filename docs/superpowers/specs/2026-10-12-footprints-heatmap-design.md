# RunNote 个人足迹与运动热力图设计

日期：2026-10-12。状态：用户已确认批准，实施与验收结果见 docs/13-footprints-heatmap-acceptance.md。

## 本轮范围与现有依据

新增受认证保护的 `/footprints` 页面，显示本人多条路线，并支持年份、日期范围与轨迹/热力图切换、点击路线进入记录详情。沿用 SvelteKit、FastAPI、PostGIS、MapLibre 与当前页面的绿色视觉风格。

已核实 `activities.user_id/activity_date`、`activity_segments.geom/segment_index` 和 `activity_points.position` 可以支撑查询；连续段独立存储，单点段的 geom 为 NULL。沿用身份依赖、统一 API 响应及 no-store 策略，不接受客户端指定 owner。没有数据库结构变更、迁移或新服务。

## 方案选择

1. 推荐：PostGIS 空间网格与路线相交，按“网格、活动 ID”去重后计数。采样密度不参与权重，查询时即时计算，不需要维护派生表。
2. 等距离重采样后映射网格：计算可控，但网格边缘可能漏掉短暂穿越，需要明确精度误差。
3. 直接 GPS 点热力：实现简单，但设备采样频率和停留产生偏差，不采用。

## 热度口径

热度表示不同运动记录经过网格的次数；同一次运动的多个段、密集点、重复绕圈在同一网格只计一次。该口径反映常跑区域，不能解释为同一次运动绕圈次数。前端显示实际次数及明确图例，单条路线沿线热度均为 1，空数据不绘制虚假热区。

后端从已过滤的本人连续段生成网格相交结果。基准网格边长为 100 个 Web Mercator 投影米；此尺度随纬度变化，不冒称全球统一地面 100 米。相交在完整分段几何上进行，不把不同段首尾连线，也不按原始点数加权。单点段仅占一个网格。跨日期变更线的边须先按短跨越拆分，避免产生横跨全球的路线和热区；极区超出 Web Mercator 可显示范围时明确提示不支持的部分，并报告数量。

用现有 PostGIS 能力生成网格、执行相交、活动级去重和聚合。对长线先拆成有界边，再生成候选格，避免整条曲折路线外包框产生大量无用网格。查询设置超时、路线/网格输出预算；超限返回可操作的错误并要求缩小日期范围，不静默丢弃活动或只显示前几条。大量路线允许按段简化展示，简化不得改变热度计算输入或段边界。

## API 与数据流

新增本人足迹查询接口，参数为配对的 `date_from/date_to` 及 `mode=tracks|heatmap`，日期采用已有 activity_date 归属和左闭右开语义。前端日期范围的结束日为包含当天，发送时转成下一日。年份模式转换为当年 1 月 1 日至次年 1 月 1 日，默认取用户时区当年。

响应包含筛选范围、活动数量、可显示/不可显示数量、GeoJSON 与聚合口径。轨迹模式每个连续段为独立 Feature，属性包含 activity_id、title、activity_date、segment_index；单点段为 Point。热力模式返回网格几何、经过活动数量及最大热度，不包含其他用户信息。记录详情继续使用现有 owner 限定接口。

## 前端与错误状态

导航新增“个人足迹”。筛选值和模式保存到 URL，刷新恢复；身份检查继续复用 layout 的保护与复查机制。筛选切换取消旧请求并防止迟到响应覆盖新结果。模式切换只加载当前模式需要的数据。

地图支持缩放、拖动、适配全部路线及点击选中记录，提供明确的详情链接；重叠路线允许选择记录，避免始终只能点击最上层。保留可访问的记录入口与热度图例。空数据、单条记录、加载、失败重试、范围过大均有独立提示。

复用 `map-style.ts` 的本地背景、OSM 栅格源和错误识别；外部瓦片不阻塞私有数据绘制。瓦片错误或超时后移除栅格，仍显示轨迹或热区，支持重试与关闭底图。保留 OSM 署名和现有隐私说明。
