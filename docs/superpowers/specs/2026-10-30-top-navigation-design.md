# 私人页面顶部导航改造设计

日期：2026-10-30。状态：设计已确认，已完成本地实现；验证结果与剩余事项见 `docs/78-top-navigation.md`。

## 背景与目标

现在私人页面左侧是一整列高饱和绿色侧栏（`--sport-sidebar` #218538），顶部每页还有一条高饱和黄色页头，两块大色块互相竞争，数据卡片夹在中间；侧栏里的白色「跑量目标」卡与仪表盘的周/月/年目标重复，在绿底上对比也很硬。

目标：

1. 减少绿色的占用面积，让数据区成为视觉重心，同时保留绿色作为品牌强调色。
2. 把侧栏的宽度还给内容区。
3. 沿用现有液态玻璃材质、弹层与动效，不新建一套。

对比图与方案取舍（A 浅色侧栏 / B 深森林绿 / C 窄图标栏 / D 顶部玻璃条）在 2026-10-30 的讨论中完成，结论是 **D 为主，中等宽度退成 C 的图标版**。

## 不在范围内

- 黄色页头、卡片、公开页面（`/p/{username}/*`、匿名展示页）的顶部导航。
- 手机和平板（800px 以下）的移动栏与下拉菜单的结构与动画（配色统一，见「颜色与令牌」）。
- 接口、权限、CSRF、隐私边界、数据计算、数据库、迁移。
- 地图、图表与主题机制（`runnote-theme`、`watchSystemTheme`）。

## 设计系统变更

这是对 `docs/design-system/README.md`「视觉不变量」的有意修改，已获用户明确同意：

- 原「绿色运动导航」改为「顶部悬浮玻璃导航，绿色用于 Logo 与当前项」。
- 原「私人侧栏与公开顶部导航分开」改为「私人顶部玻璃条与公开顶部导航分开」。
- 黄色页头、24px 卡片、胶囊控件、深色外观等其余不变量保持不变。

实现完成后同步更新 README、components、patterns、tokens。

## 布局

私人外壳（`.app-shell`）里，`.app-sidebar` 改为顶部悬浮玻璃条：

- 圆角胶囊，距视口顶部与左右各 14px；宽度对齐页面内容区（`--content-width` 加内容区水平内边距）。
- 材质用 `surface` 混合透明度加毛玻璃，边框 `border`；不新增色值。玻璃条自身走既有 `createGlass` / `.rn-glass-*` 体系，不另写折射。
- 左：Logo 加站点名。中：导航项。右：账户区（见下）。
- `.content-column` 去掉 `margin-left: var(--sidebar-width)`，顶部为玻璃条留出空间；`.navigation-progress` 不再 `left: var(--sidebar-width)`，改为整宽。
- 站点副标题不在顶部条显示，只保留在移动菜单里。
- 手机和平板（`max-width: 799px`）沿用现有 `.mobile-bar` 加下拉菜单，结构、打开/关闭动画、焦点管理与 `inert` 不变；配色已统一：`.mobile-bar` 与菜单用 `--surface` 底、`--border` 边、`--foreground` 文字，Logo 方块用 `--sport-brand` 加白字，不再是整块绿色。
- 壳层断点 B = 800px（Task 4c）：8 项（管理员）与 9 项（普通启用账户）的图标版顶部条在 800px 起都不重叠（实测见下），所以 800px 及以上是顶部条，以下是手机栏。CSS（`app.css`、`liquid-glass-controls.css`）与 JS（`enhanceNavigation`、`AppNavigation.svelte` 的 `matchMedia`）无法共用常量，各处都以注释互相指向，`top-navigation.spec.ts` 的「shell breakpoint」用 799/800/801/1023/1024 守住一致。

### 响应式三档

| 视口宽度 | 形态 |
| --- | --- |
| ≥1360px | 图标加文字；当前项为浅绿胶囊（入口为 8 个时；见下方 9 个入口的例外） |
| 800–1359px | 只有图标；当前项由滑块标出；每项有 `title` 与 `aria-label`，页面名称由页头标题呈现 |
| <800px | 手机栏加下拉菜单（结构不变，配色与顶部条统一） |

断点实测（合成夹具，窗口 700–1100px 每 10px 一档，图标版，最后一个入口右缘到账户区左缘的间距）：管理员 8 项在 730px 为 4.3px、740px 为 14.3px；普通账户 9 项在 770px 为 -0.5px、780px 为 9.5px。要求间距 ≥8px，两者都满足的最小宽度是 780px，但 9 项账户只剩 9.5px 余量：经典（非覆盖式）滚动条会占掉约 15px 布局宽度而不改变媒体查询宽度，字体放大也会吃掉余量。所以断点定为 800px（B = 800px）：800px 下 9 项账户间距 29.5px，模拟 15px 经典滚动条（布局宽度 785px）后仍有 14.5px；8 项管理员 74.3px / 59.3px。799px 以下是手机栏。

阈值以实测为准：8 个带文字的入口加账户区，在 1280–1339px 会压到账户区，所以图标版上限是 1359px（原估 1200–1300px 之间，实测不够）。必须保证不换行、最后一个入口与账户区之间至少留 8px。

普通启用账户会多出第 9 个入口「本人工作区」。9 个带文字的入口在任何桌面宽度都放不下（实测 1360px 差 89px、1440px 及以上差 45px），所以入口达到 9 个时，顶部条在所有 ≥800px 的宽度下都只显示图标（`aside` 带 `data-dense`，复用图标版样式；品牌名在 ≥1360px 仍显示）。

## 账户区

顶部条右侧从左到右：**进度环 → 主题切换（图标）→ 头像**。

- **进度环**：显示当前周期目标完成度，点开是弹层，内容复用现有 `RunningGoal`（周期、目标、已完成、统计范围说明），可调整。未设目标时显示空环与「设目标」提示。公开展示的只读视图（`readonly`）只显示、不可改。后端接口与目标计算不变。
- **头像菜单**：点开是玻璃弹层，复用 `rn-glass-menu` 与 `popover-motion.ts`。内容：姓名与「管理员模式 / 本人工作区 / 个人跑步展示」、设置（仅 `view.manage`）、退出登录。上一步刚加的「退出登录右侧圆形设置按钮」并入此菜单，不再单独存在；菜单里的「设置」保持 `aria-current`、同路径点击不重复导航、`onnav` 方向判断。
- **主题切换**：保持图标按钮，「自动」恢复入口的显示逻辑不变（`ThemeToggle` 的 `compact` 形态）。
- 身份确认中（`checking`）与未登录时的显示规则沿用现状：头像区显示占位，不显示退出、设置与进度环。

## 导航滑块与页面切换动画

- `liquid-glass-indicator.ts` 的 `createIndicator` 已支持 `axis: 'x'`。`enhanceNavigation` 增加方向参数，顶部条使用横向；移动菜单仍用纵向。
- 没有当前项的页面（如设置、个人工作区）沿用已有的 `data-idle` 隐藏逻辑。
- 滑块克隆每个导航项的图标与文字盖在上面，所以图标版不做「当前项展开文字」，否则克隆与真实项宽度不一致。跨过 800px / 1360px 断点时销毁并重建滑块，尊重 `prefers-reduced-motion`。
- 页面切换动画：≥800px 从上下滑（`page-enter-up/down`）改为左右滑，方向仍由菜单顺序与 `onnav` 决定；<800px 保持上下。`quiet-swap` 与 reduced-motion 行为不变。

## 悬浮玻璃状态

用户追加的需求：顶部条悬浮在别的组件上方时透明度更高，结构和身心健康的保存栏（`SaveBar` 的 `glass` 模式）一致，但更透明（见下）。两态：

- **docked**：页面内容还没有滑到条下面（`#main` 内容区顶部在条的下边缘之下）时，是不透明的 `surface` 卡片，无模糊、无浮起阴影。
- **floating**：内容在条下面经过时，用玻璃面板配方：`--glass-edge` 边框、`--glass-fill-base` 约 9% 的极淡底色（`--glass-opacity` × .75，默认 .12 时约 9%，玻璃调节器可调；对照 Apple Liquid Glass 演示：内容透过玻璃清晰可见，仅靠细亮边与边缘折射定形）、`--glass-sheen` 内高光与 `--glass-shadow` 轻阴影（`0 .5rem 1.5rem`），并通过 `attachMenuGlass` 折射（与玻璃按钮同一套光学）；导航文字与品牌名不加光晕或文字阴影（会在字形边缘留白边）。悬浮时未选中的导航文字与图标改用 `--foreground`（灰色 `--muted-foreground` 在黄色页头上太弱），docked 仍是灰色；当前项保持 `--sport-nav-active-ink`，悬停仍由滑块表现。WebKit 无法折射，用 `.rn-frosted-glass` 磨砂玻璃（`attachFloatingGlass` 在 WebKit 里只加这个类；`backdrop-filter: blur(14px) saturate(1.5)` 加约 60% 的 `--surface` 底色，亮边与较轻阴影沿用），避免近乎不透明的静态边缘让下面的内容像重影一样透出来；Safari 比 Chromium 不够清透，用户已接受，且只在 Playwright 的 WebKit 引擎验证过；Firefox 保留模糊回退；`prefers-reduced-transparency` 与 `forced-colors` 保持实心卡片。
- 只作用于桌面顶部条；移动栏、移动菜单与弹层不变。

## 颜色与令牌

- 玻璃条用既有令牌（`--surface`、`--border`、玻璃相关变量）。
- `--sport-sidebar` 不再给任何导航上色：桌面顶部条、手机栏与手机菜单都走 `--surface` / `--border` / `--foreground`，导航项用 `--muted-foreground`，Logo 方块用 `--sport-brand`，玻璃按钮用中性 `--glass-surface` 一套。`--sport-sidebar` 只剩站点设置预览（`.preview-side`、`.preview-mark`）使用，令牌保留；`--sport-nav-hover` 用于导航项悬停；`--sport-nav-active` / `--sport-nav-active-ink` 用于当前项。令牌名称与值尽量不动，只在文档里更新用途描述。
- 深色外观见 `2026-10-30-dark-theme-warm-charcoal-design.md`（暖炭灰加薄荷绿），手机栏与菜单同样跟随。

## 分两步实施

风险点是改动文件多、横向滑块在图标版中要重新校准，所以分两步，每步各自验收。跑量目标卡不能先藏起来（现有多个 UI 规格依赖它），所以进度环放在第一步：

1. **骨架、进度环与响应式**：顶部玻璃条、内容区布局、进度环加目标弹层、三档响应式、横向滑块、左右页面动画。账户区的头像与退出、设置暂时沿用现有按钮，在桌面宽度下收成图标。
2. **头像菜单与文档**：头像菜单（含姓名与模式、设置、退出登录），桌面隐藏第一步里临时排出的图标按钮（移动菜单保留原有内联版本）；更新设计系统文档、展示页与像素基线。

每一步都同步更新受影响的测试。

## 测试与验证

- 现有 UI 规格里引用 `.app-sidebar` 的约 27 行，分布在 `ui-shell`、`site-settings`、`admin-users`、`sport-detail`、`liquid-glass`、`crossbrowser-glass`、`theme`、`wellbeing` 八个规格里。决定保留 `.app-sidebar` 类名与 `id="app-navigation"`，只改样式与结构，避免成批改选择器；断言里依赖「左侧」「宽度 15rem」「纵向排列」的少数用例按新形态改写。
- 现有断言「每个私人路由都有跑量目标区域」（`ui-shell.spec.ts`「unified sports shell」）要改为进度环；设置页高亮、`onnav` 方向、滑块隐藏等已有断言按新结构调整。
- 新增：三档宽度的布局与「最后一个入口不压到账户区」断言（1440、1360、1359、1280、1100、1024、800），以及 9 个入口的普通账户在 800、1024、1360、1440、1680 全部为图标版且不重叠、图标版的 `title` 与展开行为、头像菜单键盘操作与 Escape 焦点回退、进度环弹层与只读视图、横向滑块位置、页面左右动画方向。
- 合成 UI 测试不需要新增接口。
- 运行：`pnpm check`、`pnpm test`、相关 Playwright 配置（`playwright.ui.config.ts` 的受影响规格，`design-system.config.ts` 的像素基线需要审阅后更新）、`pnpm build`。真实后端的 e2e 不受影响，但需要按 `docs/00-legacy-readme.md` 的方式确认没有回归时才能声称。
- 视觉验收：1440 / 1360 / 1280 / 1100 / 1024 / 800 / 799 宽度（含 9 个入口的普通账户在 1440 的图标版）与 361px 手机，浅色与深色，系统外观、手动明暗；键盘焦点可见；`prefers-reduced-motion`；身份确认中、未登录、只读展示视图。

## 风险

- 顶部条宽度：8 个入口加进度环、主题切换、头像，在 1360px 以下最紧。实测 1280–1339px 时 8 个带文字的入口会压到账户区，所以图标版的上限定为 1359px（原定 1279px）。
- 图标版里滑块位置要在断点切换与窗口缩放时保持准确，最容易出现错位。
- 页面切换改成左右滑后，与菜单顺序的对应关系要在 UI 测试里钉住。
- 像素基线（`design-system.config.ts`）会因导航形态变化而改变，需要人工审阅，不能直接 `--update-snapshots`。
