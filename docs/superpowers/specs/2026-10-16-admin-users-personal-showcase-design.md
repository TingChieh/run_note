# 后台多账号管理与独立个人展示页设计

日期：2026-10-16。状态：用户已确认，按本设计实施。

## 已明确的需求

- 后台支持用户列表、新增、编辑、禁用与重置密码。
- 主域名继续固定展示 `SITE_OWNER_EMAIL` 对应站主，默认值见 `backend/app/core/config.py`。
- 其他用户拥有独立链接，展示与站主相同的数据汇总、记录列表/详情、足迹墙、足迹地图、目标与已成功 AI 报告。
- “相同内容”包含完整轨迹和精确起终点；仍排除邮箱、私人备注、源文件、密码/会话及供应商信息。
- 自助注册继续关闭，统一从 `/admin` 登录。账号由站主创建和管理。

## 现场依据

- 当前管理员由 `SITE_OWNER_EMAIL` 识别，登录和 `get_identity` 均拒绝其他账号；放开登录时必须拆分“有效登录身份”与“站主管理权限”。
- `users` 已有唯一 email、username、昵称、时区、简介；没有启用状态或完整展示开关。`auth_sessions` 已支持撤销。
- 原本人业务查询使用登录用户 ID，可复用为各用户的私有工作区，不能继续把展示站主等同于当前登录用户。
- 新 showcase 接口固定站主、独立白名单；可复用查询与序列化为个人展示接口，资源归属仍必须在 SQL 中限定。
- `/u/{username}` 已是旧版公开摘要页。不能直接将已有摘要链接升级为完整轨迹公开链接。
- 迁移目录当前到 `0010_footprint_snapshots`；新增版本须再次核对唯一 head 和下一个序号。
- 当前工作区存在大量既有未提交修改，扩展只能增量实施。

## 实现方式比较

| 方案 | 影响 | 选择 |
| --- | --- | --- |
| 同一应用内分离站主管理、本人工作区和具名公开展示 | 复用指标、地图与页面；身份与展示对象清楚分开；一次部署 | 推荐 |
| 直接扩展旧 `/u` 摘要页并放开所有账号 | 改动少，但改变旧链接的公开范围，容易使历史资料意外公开 | 不采用 |
| 每个用户部署一个独立站点 | 数据隔离直观，但域名、备份、升级和部署成本按用户增长 | 当前不采用 |

## 访问与权限

### 站主

- 仍是唯一账号管理员，以服务端 `SITE_OWNER_EMAIL` 精确识别；不增加角色授权/转让界面。
- `/admin/users` 提供分页列表、邮箱/用户名搜索、启用状态筛选、创建、资料编辑、启用/禁用、公开展示开关、重置密码和复制展示链接。
- 管理操作仅涉及账号和访问状态；不提供模拟登录、跨用户导入或修改运动数据。
- 不允许禁用站主、关闭站主现有主域名展示、修改站主登录邮箱或用户名；站主密码用需要当前密码的本人修改流程。
- 不提供硬删除，禁用保留全部记录。

### 普通用户

- 后台创建并启用的账号可从 `/admin` 登录，进入 `/workspace/dashboard`；工作区覆盖记录导入/编辑/删除、足迹、目标、AI 和本人设置。
- 本人数据操作使用真实登录用户 ID；不能管理账号、重置他人密码或查询他人私人信息。
- 登录后访问站主主页或他人公开页时，继续是只读访客，不显示他人的写入控件；知道资源 UUID 也不能越权。
- `/workspace` 的数据来源与公开展示开关无关：关闭公开展示后，本人仍可管理自己的数据。

### 访客

- `/` 及现有主展示路由保持固定站主。
- `/p/{username}` 是个人展示入口，进入该用户的数据汇总；子路径为 `/dashboard`、`/activities`、`/activities/{id}`、`/activities/wall`、`/footprints`、`/ai`。
- 个人展示内的导航、记录链接、分页、返回与复制链接都保留 `/p/{username}` 前缀，不能跳回站主数据。
- 用户名创建后固定，作为独立展示链接地址的一部分公开，避免分享链接失效；可以编辑昵称、邮箱、简介、时区。
- 不存在、未启用或未开启展示的非站主统一返回 404；不暴露停用原因。
- 完整展示页始终为只读，即使登录，也通过工作区入口管理本人数据。

## 用户管理行为

- 新增：邮箱、用户名、昵称、时区、初始密码、账号启用开关、公开展示开关。密码 12–128 字符，沿用现有 Argon2 和输入校验。
- 新账号默认启用登录，默认不公开展示。创建表单可显式开启展示，并说明全部历史与未来记录、完整轨迹和精确起终点都会公开，原 visibility 不限制此页面。
- 历史非站主账号默认不可登录、不可完整公开，由管理员逐个启用；不批量公开或更改历史记录。
- 编辑资料只应用提交字段；重复邮箱/用户名返回明确领域错误。修改普通用户登录邮箱后撤销其全部会话。
- 禁用立即撤销全部会话，拒绝重新登录、本人 API 和个人展示；重新启用不恢复旧会话，也不自动重开公开展示。
- 关闭公开展示不禁用登录；所有具名展示资源和直接路线/报告地址须重新检查开关，不能只在页面入口校验。
- 重置普通用户密码须二次确认，设置新密码并撤销全部会话；密码不回传列表、不记录日志、不发送邮件、不写入 URL。站主可通过本人流程修改自己的密码。
- 登录用户不能操作 `/admin/users` 时，页面与 API 都拒绝；后台安全边界由 FastAPI 执行。

## 接口与数据结构

- 新增管理员 `/api/v1/admin/users` 列表/创建，以及按 ID 的资料更新、状态更新和密码重置端点；沿用信封、严格请求体、limit/offset、CSRF/Origin 和中文领域错误。
- 新增 `/api/v1/showcase/users/{username}/...` 公开读取，与站主现有 showcase 资源一致，始终先解析展示用户及有效状态，再以其 ID 限定资源查询。
- 本人读写接口保持所有权过滤。拆出仅站主可用的 admin 依赖，不能用放开普通身份的方式放开账号管理。
- 认证响应增加由服务端计算的管理员标记，前端运行时校验；展示响应不增加登录邮箱、权限或内部 user ID。
- 用户表新增登录启用与完整展示标志。历史行两项默认关闭；配置站主作为受保护的特殊身份继续有效，不受普通账号开关影响，后台返回计算后的有效状态。普通账号创建时显式设置状态。
- 所有账号状态/密码变更与登录沿用 users 行锁并撤销会话，避免跨 worker 的并发登录绕过禁用/重置。
- 旧摘要分享体系不升级为完整展示。禁用账号也需停止其旧公开摘要和分享读取；站主现有行为不变。
- 私有 AI 生成仍受本人同意/配额约束；公开读取只取已成功报告，不调用供应商、recover 或清理写入。
- SSR 代理固定源、七项头白名单、11 MiB 上传限制、指标计算和导入互斥保持。

## 前端实现与外观

- 复用现有展示页面、导航、图表、地图、表单与设计系统。提供明确的页面数据上下文，分别表示固定站主、具名公开用户、真实登录用户；不使用跨请求全局变量。
- 仅对共享页面增加必要上下文和路径处理，避免复制整套业务逻辑；现有主路由保留站主本人管理能力，普通用户在主路由只能只读。
- 用户列表用原生可访问表格和局部滚动；手机操作可换行。新增/编辑/重置复用表单和 dialog 模式，失败保留草稿，成功反馈明确。
- 请求有 disposed 和递增令牌；切换用户或过期立即清除旧私有状态。验证明暗主题、窄屏、键盘/焦点与加载/空/错状态。

## 迁移与部署边界

- 本扩展需要手写数据库迁移；降级在存在启用或公开的普通用户时拒绝丢弃状态，不能静默恢复开放权限。
- 实施阶段只允许在独立、显式允许的 `_test` 数据库升级和回归；不在开发库自动迁移，不修改 `.env`、密钥、真实账号或真实记录。
- 新迁移会使旧数据库 readiness 不匹配。交付时明确列出开发实例尚未升级/加载，不能宣称上线可用。
- 开发/生产升级另需明确授权并执行备份、恢复演练、单次升级、账号与数据复核。原生 systemd/Caddy 方案继续使用，不引入容器。
- 离线建号工具继续仅初始化受保护站主；不把正式自助注册重新打开。

## 验收标准

1. 站主能列出、新增、编辑、禁用/启用、重置普通账号，普通用户/匿名直接调用均被拒绝。
2. 禁用、改登录邮箱、重置密码后，跨 worker 旧会话失效；重启服务后状态仍存在；受保护站主不会被锁出。
3. 两个合成用户的工作区数据分离，站主主页固定不变，所有其他用户页面、路线及报告均限定具名展示对象。
4. 未开启展示的用户及其资源返回 404；开启后完整页面和精确轨迹可匿名访问；关闭/禁用后所有直接读取立即失败。
5. 不公开邮箱、私人备注、源文件、密码/会话、供应商错误；报告读取不产生供应商调用或管理事务写入。
6. Chrome 合成 UI 验证新建/编辑/禁用/重置、两用户链接浏览、路径保留、明暗/手机/键盘；PostGIS 独立库验证权限和事务。
7. 实际执行相关单测、类型检查、构建、Ruff、独立库迁移和集成回归，分开记录通过/失败/跳过/未运行。
