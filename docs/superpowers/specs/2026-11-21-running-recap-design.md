## 一、视觉方向

| 方向 | 浏览体验与分享形态 | 取舍 |
| --- | --- | --- |
| **A · 跑步年鉴（推荐）** | 单页纵向阅读。总里程做视觉焦点，次数、天数、用时和配速归为一组，里程柱图呈现周期节奏。竖版分享图保留同样的信息层级。 | 一屏可扫读，键盘、平板与少量记录都容易支持。主要依赖现有统计及设计令牌，足迹和故事可作为后续章节。 |
| B · 分屏故事 | 每屏一张叙事卡，按总量、节奏、成绩依次翻页。可生成一张封面或选取某屏。 | 自带揭晓节奏，适合工作项 19；目前聚合素材较少，翻页增加操作、焦点管理、减少动态效果和多图导出的成本。 |
| C · 足迹封面 | 区域轮廓或去识别化的足迹作为年度主视觉，数字从属于地理分布。 | 对有轨迹且跨区域的年份辨识度高。手动记录、单城市和地图未就绪的年份需要平行降级设计；真实路线进入分享图会增加位置再识别风险。 |

推荐 A。一个周期有一张可浏览的回顾页和一张图片。页面末尾在内容结构上可以接入工作项 19 的章节，工作项 15 发布时省略故事占位和入口。

## 二、入口和页面编排

从「个人记录」中已有月度／年度报告卡增加「查看跑步回顾」。传递卡片上**已加载**的周期，生产建议入口为本人 `/workspace/records/recap?period=year&year=2025`（月度另传 `month`）。站主 `/records` 和本人 `/p/{username}/records` 上的入口同样进入本人的工作区，返回链接指向本人的个人记录。同一页支持历史深链接、前后周期和回到本月/今年，重新进入时优先用链接周期，无参数时默认本人时区的今年。现有入口判断为 `viewsOwnRecords`，新增页面另外使用服务端认证门控，直接输入地址也只能看本人。入口与调用方见 [周期报告设计与验收](../../90-period-reports.md) 和 [个人记录路由](../../../frontend/src/routes/records/+page.svelte)。

| 区块 | 页面与状态 | 来源 |
| --- | --- | --- |
| 周期标题与切换 | 页标题显示已呈现的年份／月份，显示实际日期范围与当前周期的「进行中 · 截至 MM.DD」。延续分段控件、月份选择器、年度选择和步进操作。 | 同一 `PeriodReport` 的周期字段，复用 `PeriodReportCard` 的切换及刷新行为。 |
| 周期总览 | 总里程为主数字，跑步次数、跑步天数、总用时、平均配速按顺序阅读。部分计时用简短注释交代覆盖记录，缺失值显示 `—` 并补充读屏说明。 | `distance_m`、`activity_count`、`activity_days`、`duration_sum_seconds`、`avg_pace_seconds_per_km`，辅以 `known_duration_count`、`missing_duration_count`、`pace_eligible_count`。 |
| 里程分布 | 年度按月，月度按周，周一开始且首末周裁到自然月。高亮里程最高的桶并给出日期与里程；并列时提示并列，可按时间排序。整段里程为零时去掉峰值文案。图下用 `<details>` 提供完整数据表。 | 用报告返回的 `date_from` 与 `date_to` 请求已认证的 `/api/v1/statistics/trends` 的 `month` 或 `week`。现有前端 `readTrends(year, ...)` 固定查整年且指向 showcase，复用响应校验和桶连续性检查，为本人新增明确起止范围的调用并保留旧调用方。 |
| 分享 | 「生成分享图」放在趋势标题旁，图表高低和屏幕主题变化不改变控件含义。启动后就地打开预览，提供保存与系统分享。 | 用同一周期的五项聚合、范围和已验证的趋势桶构造独立的导出数据。 |

日期按活动自己的 `activity_date` 归属。周期为 `[date_from, date_to)`，页面以含末日的日期范围呈现。当前周期由服务端按用户时区截到 `today + 1 day`。缺计时用现有规则优先取 `timer_seconds`，否则回退 `elapsed_seconds`。平均配速依合资格记录的总用时与有效距离加权。已过去的空桶显示零，未到的周期部分留空且在表格标为未到，避免把剩余月份读成零里程。看表、生成图时均使用服务端聚合，不在客户端按活动列表重新求和。核对 [统计聚合与周期边界](../../../backend/app/modules/statistics/service.py)、[现有响应解析](../../../frontend/src/lib/api/period-report.ts) 与 [趋势客户端](../../../frontend/src/lib/api/statistics.ts)。

首次加载使用 `PageSkeleton` 或区块状态。切换时保留上一周期的完整对比度和原来的标题，状态单独播报正在读取的目标周期。新周期装载中暂停生成图，避免导出上一周期。聚合没有记录时显示空态并保留周期选择。趋势失败时保留总览，在趋势区提供重试，初版待同周期数据完整后才开放分享。每次切换关联期次及请求令牌，卸载、过期响应和 401 清理数据与预览。两次查询可能跨越一次导入或删除，发现同范围的完整桶总里程与报告不一致时可重新载入并核对一次；持续不一致时仅当前报告可见，提供趋势重试。只有实测需要原子快照时才考虑服务端合并读取。

## 三、分享图片与浏览器导出

推荐单一竖版 **1080×1920 PNG（9:16）**，与路线海报宽高一致。安全留白从样稿的左右约 84 px 起稿。版面从上往下是 RunNote 品牌及周期范围、周期标题、突出总里程、里程分布和四项次级指标。当前周期须把截止日像素化到图内，缺失配速或不完整计时用简明注记，导出小样在约 360 CSS px 宽下核对单位和月份标签。默认随页面实际明暗外观，预览允许显式选择，导出完成时冻结所选主题和期次。品牌建议固定为 RunNote 字标与通用首字母，允许部署自定义标识的方案交负责人决定。

点击一次即按当前周期生成预览。初版使用专用 Canvas 2D 布局，把白名单字段画入固定像素尺寸，用 `toBlob` 以 `image/png` 导出。生成逻辑在浏览器端按需加载，等字体可用后布局，中英文标题和指标用 `measureText` 检查，保留下载文件名 `runnote-recap-2025.png`、`runnote-recap-2025-10.png`。预览采用对象 URL，换周期、关闭、卸载和过期时释放。保存使用原生下载链接。用 `navigator.canShare({ files })` 检查能力，通过时提供单独按钮，在用户按下按钮时调用 `navigator.share({ files })` 提交已生成的文件。取消系统分享可返回预览，渲染失败时重试。样稿中的「保存 PNG」下载预渲染的合成样图，生产方案的 Canvas 与系统分享留待批准后实现。

## 四、适配、无障碍与性能

- **桌面**。保留 ≥800 px 的导航壳断点，标题、周期放同一行。左侧突出总里程，右侧四项指标 2×2，趋势和表格全宽。1440×900 首屏同时看到趋势与分享入口。
- **平板**。768×1024 采用项目窄壳层，总览在 640 px 以上仍为两栏，缩减间距及轴标密度。周期控件允许换行，趋势与表格不横向滚动。
- **手机**。390×844 使用单列，总里程在上，四项指标 2×2，同序阅读；周期分段占满一行。分享入口与图表标题能换行，操作区至少 44 px。320 px 和 200% 缩放须额外核对长数字、中文与月份标签；必要时减少轴标签，表格保留全部日期。
- **主题**。使用 `--background`、`--surface`、`--foreground`、`--muted-foreground`、`--primary`、`--border`、`--header-tint` 及现有圆角、间距和字体阶梯。浅色总览用现有淡奶油色，深色改为暖炭灰表面，绿色聚焦里程与最高柱。样稿用局部 64 px/48 px 的主数字试视觉比例，生产默认现有 48 px `--text-display`，大字例外待确认。 [令牌](../../design-system/tokens.md) · [组件](../../design-system/components.md) · [页面模式](../../design-system/patterns.md)
- **无障碍**。原生链接和按钮、逻辑标题层级、指标 `dl`、带单位和表头的数据表。峰值同时用文本标明，避免单靠色差。焦点可见，分享对话框可用 Escape 结束，关闭时焦点回触发器。普通文字对比度目标 4.5:1，关键控件与图形目标 3:1，同时测强制颜色和减少动态效果。分享预览提供含周期和指标的可读文字摘要。
- **性能**。首屏只取本人周期聚合和精确裁切的趋势，不拉取活动详情、轨迹、地图、图片或 AI。新周期可取消在途请求；短柱图使用固定槽位，预览延后生成，PNG 每次仅保留当期一份。实施时测低端手机的首开与首次导出，以该次基线决定优化，不预加载地图、动画或视频导出模块。

## 五、本人和分享边界

工作项 15 只提供本人私有页面和用户主动保存／系统分享的静态图。公开个人主页不出现入口，服务器不生成公开链接、永久图片地址或图片存档。聚合默认代表该账号在已选周期的本人活动，包括私有记录的聚合贡献；分享确认前预览会明确标注「含私人记录的汇总」，取消不发送。是否首发需要「仅公开记录」口径由负责人决定。若启用，必须在服务端过滤 `visibility = 'public'`，并确保总览、趋势和导出使用同一个范围。

图像白名单只含周期、截止日、聚合数字、无地理坐标的里程分布及通用品牌。省略姓名、邮箱、用户名、账户／活动 ID、活动标题及备注、文件名、轨迹、起终点、地名、个人头像、原始 GPX/TCX、身心健康字段、网址和二维码。生成与预览无需网络和第三方服务；如选用自定义品牌只允许同源站点公共标志，并检查站点名作为身份线索的影响。保存到设备或系统分享后由用户决定接收方，服务端无需保留任何分享载荷。未来如要添加公开页面，需另行评审白名单与可见性授权。

## 七、获批后的实施和验收

1. 确认下列决策。接上本人入口、周期参数、报告与裁切趋势客户端，验证同周期、截止日、空态、错误和路由权限；预计复用现有 API，无迁移。趋势在当前年切到同周期时需同时处理闰日、跨年周、未来活动以及历史空月。重点测 401、返回与快速切换。
2. 接入回顾布局、主题和语义数据表。补合成 API 与定向 Playwright，检查 1440×900、768×1024、390×844、320 px、200% 缩放和两个主题；检查长用时、超大里程和单位。实际绘制采用同一报表事实来源。
3. 实装 Canvas 版式和预览。验收 PNG 尺寸、年度与月度的文本一致性、两主题、进行中截止、字体缺字与失败重试；真机 iOS Safari 及 Android Chrome 检查保存和系统分享，桌面 Firefox 检查下载回退。核对匿名与其他账号无入口、登出后无旧图、导出不发后端或第三方请求，图片只呈现白名单。
4. 运行项目验证入口及对应的合成 UI 与真实后端权限链路，按仓库规则使用隔离的 `_test` 库。工作项 19 获批时另行比较地理归类覆盖、缓存时间和分组稳定性，决定是否追加独立的故事聚合接口。

主要风险是周期范围漂移、跨请求统计不一致、移动浏览器保存体验、私人数据被用户二次传播，以及总体量过大时数字换行。用同一范围、请求令牌与一致性检查控制数据风险，预览披露分享口径并让用户主动保存，再通过多浏览器和极端样本验证版式。工作项 19 的缺口是位置覆盖、分组缓存和长轨迹的成本，单独设预算和降级验收。

| 年度故事首批内容 | 先做本年首跑、最长一跑和距离档最佳；城市、常跑路线和动画在覆盖验证后排期 | 可以选地图主导方向，但需提前安排缓存性能、未知区域及位置隐私评审。 |
| 主数字字号 | 生产使用设计系统 `--text-display`，样稿 64 px 仅作评审选项 | 局部允许 64 px 时要增加大值、长单位和缩放检查。 |
