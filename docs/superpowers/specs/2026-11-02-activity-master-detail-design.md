# 跑步记录：时间线列表 + 桌面左右两栏 设计

日期：2026-11-02。背景：[80](../../80-activities-views.md) 把“足迹墙”并入跑步记录。原来的活动卡片（约 255px 高，两列）太大，三列紧凑卡片又显得碎。用户在效果图里选定：手机用带日期的时间线，桌面用左右两栏（左列表，右地图与详情），导入区块折叠。

## 目标

1. 活动列表改成按月分组的时间线：月份胶囊 + 当月合计，左侧日期列（日、星期），右侧一张轻量卡片（路线缩略图、标题、成就/标签标记、距离/用时/配速）。
2. 桌面（≥1024px）左右两栏：左栏固定宽度的时间线，选中一条后右栏显示它的路线地图与详情（指标、开始时间、完整度、编辑/删除/生成分享图、“查看完整详情”链接）；右栏吸顶。手机与窄屏只有时间线，点击进入活动详情页（行为不变）。
3. 导入区块（GPX/TCX 与 Mi Fitness）折叠到一个“导入轨迹”按钮后面，不再把列表推到页面下方。

## 非目标

- 不改后端、接口、数据库、鉴权与公开数据边界；不新增请求类型（右栏复用现有的 `readRoute`）。
- 不改活动详情页本身；不改分页大小（20 条）。
- 不做服务端的月度汇总接口。

## 设计

### 时间线（`ActivityTimeline.svelte`，卡片仍是 `ActivityCard.svelte`）

- 按 `activity_date` 的年月分组，保持接口返回的顺序（日期降序）。月份胶囊旁的合计：这一组在本页里完整时显示“N 次 · X km”；被分页截断的组（第一组且 offset>0，或最后一组且后面还有）显示“本页 N 次 · X km”，不把本页合计冒充整月合计。
- 每行：日期列（日、星期）+ `ActivityCard`。卡片去掉“公开展示”默认标记，只标“未公开”（`visibility` 不是 public 时）和“时间不完整”；去掉页脚“查看活动 →”。标题单行截断，成就/分类/标签在第二行，第三行是距离（加粗）、用时、配速。
- 批量管理：编辑模式下卡片行首出现复选框，行尾出现“编辑 / 删除”小按钮（沿用原有 `onselect`/`onedit`/`ondelete`，44px 点击目标）。

### 左右两栏（`/activities` 页）

- `wide` = `matchMedia('(min-width: 1024px)')`，只在客户端判断；窄屏不挂载右栏，所以不会白读路线。
- 桌面时卡片是链接（`href` 仍指向详情页，Ctrl/Cmd/中键照常打开）；普通点击改为选中，不跳转。选中项高亮并 `aria-current="true"`。上下方向键移动焦点并选中，Enter 在选中项上进入详情页。
- 选中的记录 id 写进地址 `?id=`（`replaceState`，不产生历史记录）；加载列表后：地址里有且在本页则选中它，否则选中第一条；换页、删除后同理。
- 右栏（`ActivityPreview.svelte`）：标题、日期与星期、标记；`RouteMap`（与详情页同一组件，选中另一条时原地更新，读取下一条路线期间保留旧路线）；距离/用时/配速/平均心率；热量、步数、开始时间、完整度；编辑/生成分享图/删除（仅 `view.manage`）；“查看完整详情 →”。路线读取失败只在右栏显示重试，不影响列表。
- 吸顶：`position: sticky`，顶部留在固定顶栏下方（同 `.site-layout > aside` 的偏移）。

### 导入折叠

- 列表标题行右侧一个“导入轨迹”按钮（`aria-expanded`、`aria-controls`），展开/收起两个导入区块。区块始终挂载，用 `hidden` 收起，所以选好的文件和批量导入进度不会丢。
- 默认收起；记录为空、导入进行中、或有结果提示（成功、警告、错误）时自动展开。仅 `view.manage` 显示。

## 风险与取舍

- 现有测试大量直接操作导入表单：需要一个夹具先展开导入区；断言“公开展示”“查看活动”的用例要改。
- 右栏会多读一次选中项的路线（缩略图自己也读一次）。先不做共享缓存。
- 地址里的 `?id=` 指向别的页的记录时回退到第一条；不为此单独请求。

## 验证

桌面/手机/深浅色截图；Playwright：分组与合计（含被截断的组）、选中与地址同步、方向键、窄屏无右栏且点击进详情、编辑模式的批量选择与删除、导入折叠与自动展开、右栏路线失败重试。
