# 详情足迹堆叠与记录切换

## 使用方式

保留左侧标题、说明与全部足迹入口，右侧卡片用满可用宽度，按实际宽度展示相邻运动记录，取消固定三张。卡片宽 9rem，仅在边缘重叠 0.5rem，保证内容可见；层级从选中项向两侧递减；从左到右按活动日期和 UUID 倒序，最新在最左，首尾不循环。

箭头放在卡片两侧，删除底部的计数与“查看该记录”。点击箭头或卡片直接切换完整跑步记录，包括标题、指标、路线、管理与分享状态，同时替换当前详情地址，不累积详情浏览历史，返回仍回原列表/足迹墙页码。

选中卡片抬高并跟随鼠标倾斜。复用 Svelte 的 keyed FLIP 和进入/离开过渡，让相邻卡片移动；缩小动态效果时关闭动画。保留箭头键盘焦点、中文名称和仅供读屏的当前记录说明。手机仍把箭头放在卡片两端，按空间缩减卡片数。

## 数据和生命周期

继续复用活动列表分页缓存与二分定位。切换先读取目标详情与路线，期间保留旧记录和卡片、禁用重复操作；详情读取失败保留旧 URL 和内容并允许重试。路线失败允许展示新记录与路线重试提示。401 清除私人状态，disposed 和请求令牌丢弃过期响应。

详情内部以 SvelteKit shallow replace 更新 URL，保留卡片组件、分页缓存与原来源历史；刷新使用当前地址加载正确记录。根布局不为 shallow 导航隐藏整个页面。管理、分享区域按活动 ID 重新挂载，避免上条记录的私有状态混入新记录。只复用现有接口，不变更数据库或公开行为。

## 验证

Chrome 合成 API 检查右侧区域利用率、动态卡片数、左右按钮位置、全部详情同步切换、URL/刷新/返回来源、跨页缓存、实际动画运行、首尾、失败与慢请求、过期路线隔离、401、窄屏深色/触屏/键盘/减少动态效果。执行类型检查、单元测试与构建；不操作开发库，不提交或推送。
