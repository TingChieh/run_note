# RunNote 跟随设备的夜间模式（已实施）

## 目标与行为

默认根据设备的浅色／深色外观自动切换，依据浏览器的 `prefers-color-scheme`，而非时间或定位。首次访问、刷新和页面跳转均应用当前设备主题；页面打开期间设备外观变化后立即更新，无需刷新。未声明深色偏好的设备继续显示浅色主题。

覆盖登录、注册、私人页面、公开活动和分享页面。保留现有绿色运动风格；深色模式采用深绿灰背景、较浅的卡片和高对比文字，降低大面积黄色标题区域的亮度。

## 方案比较

1. **推荐：CSS 跟随设备，绘图组件少量监听。** 使用媒体查询和现有主题变量，让普通页面在首次渲染时直接获得正确颜色。Canvas 图表、WebGL 地图通过 `matchMedia` 监听设备变化，更新绘图颜色并在销毁时移除监听。无需主题持久化。
2. **增加浅色／深色／跟随设备三种选择。** 能覆盖设备设置，但需要设置入口、偏好存储及首屏初始化。本次需求明确为自动转换，暂不加入这部分交互。
3. **统一依赖 JavaScript 切换根节点类名。** 样式控制集中，但增加首屏初始化和脚本失效时的处理；已有 CSS 变量足以支持方案一。

## 文件修改计划

- `frontend/src/app.css`：补充深色主题变量，处理根节点与 `.sport-theme` 的覆盖关系，适配标题、导航选中状态、反馈和表单焦点；把状态颜色和必要的运动配色纳入变量。
- `frontend/src/app.html`：声明页面支持浅色与深色原生控件。
- `frontend/src/lib/components/RunningGoal.svelte`、`CalendarGrid.svelte`、`ProvinceMap.svelte`、`RouteThumbnail.svelte`、`GoalOverview.svelte`：将影响深色可读性的固定颜色替换为语义变量。日历活动档位和图例使用相同颜色，保持数据含义。
- `frontend/src/routes/activities/+page.svelte`、`activities/[id]/+page.svelte` 及 AI／分享相关组件：适配固定警告、错误文字、背景与分隔线。
- `frontend/src/lib/components/TrendChart.svelte`：通过实际主题变量设置坐标轴、网格、数据系列和提示框颜色，在设备主题变化时更新现有图表，保持选中的指标和数据。
- `frontend/src/lib/components/RouteMap.svelte`、`FootprintMap.svelte` 与必要的 `frontend/src/lib/api/map-style.ts`：适配地图背景与控件，深色时降低现有栅格底图亮度。沿用现有 OpenStreetMap 来源，保持路线、标记和热度图例含义；主题切换只更新绘制属性，保留视野和选中路线。
- `frontend/tests/ui/theme.spec.ts` 与 `frontend/playwright.ui.config.ts`：加入主题浏览器验收。

实现时仅修改确实存在固定颜色问题的文件；无需修改后端、数据库、认证、API、隐私边界或安装依赖。

## 生命周期与异常

普通页面样式由浏览器媒体查询处理，避免等待挂载后才应用主题。绘图组件在客户端挂载后读取媒体查询和 CSS 变量，主题变化不触发业务请求或重建地图数据。组件卸载移除监听，避免重复监听和已销毁实例更新。图表或地图加载失败时保留现有反馈与数据表退路。

## 验收

1. 真实 Chrome 模拟浅色和深色设备设置，覆盖登录、仪表盘、活动详情、足迹、设置、AI、公开／分享页面的代表性内容；检查背景、卡片、文字、错误提示、原生表单、图例与控件。
2. 同一页面深色切浅色再切回深色，确认无需刷新，图表和地图同步变化，筛选、地图视野与选中状态保留。
3. 深色模式检查桌面及 390px／320px 手机宽度、键盘焦点、导航选中状态和横向溢出，保留截图证据。
4. 使用隔离 UI fixture 验证，避免真实私人数据或付费 AI 调用；运行前端类型检查、相关单元测试和生产构建。任何无法验证的项目单独记录。

## 范围边界

本次只加入自动设备主题。手动覆盖开关、按时间切换和用户账户主题持久化不在本次范围。保留现有浅色表现，不提交或推送 Git 变更。
