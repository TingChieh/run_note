## 现有代码与保障

- `/footprints` 的 `FootprintMap.svelte` 使用 MapLibre、`fit`/`frameInitial`、本地轨迹与热力图层及就绪标记 `footprint-map-ready`。活动详情 `RouteMap.svelte` 使用 MapLibre，本地轨迹 render 后设置 `route-map-ready`，`scheduleFit` 与 `recenter` 管理适配视图。`ReplayPlayer.svelte` 是独立 MapLibre 回放，拥有 `replay-map-ready`；本轮矩阵未测回放性能。
- `/dashboard` 的 `ProvinceMap.svelte` 动态载入 Three.js，`switchProjection`/`setMode` 在球体和墨卡托平面之间执行 1100ms 过渡；`province-touch.ts` 的 `TouchGestureTracker` 与捏合算法处理触摸。渲染器发布 `data-view-*` 供现有测试观察。它不是 MapLibre 相机。
- `lib/map/maplibre.ts` 的 `loadMapLibre` 延迟载入库、CSS 与 worker；`footprint-display.ts` 的 `footprintDisplayData` 限制展示点数，`footprint-cities.ts` 与 `footprint-cities.worker.ts` 定位城市，`globe-geometry.ts` 提供投影、边界适配和几何生成。

- 既有 `tests/unit/{province-touch,basemap-controller,map-style}.test.ts`、`tests/ui/{milestones,footprints,activity-replay}.spec.ts` 分别覆盖触摸数学、底图边界与失败恢复、地图和回放交互。`playwright.ui.config.ts` 启动 UI 合成 API 与 Vite；`scripts/verify.py` 统一执行 Vitest、类型检查，并按选项安排浏览器及数据库测试。

## 环境与方法

Fedora Linux 7.3.4-300.fc45.x86_64，Intel Core Ultra 5 235H（14 逻辑 CPU），系统图形设备 Mesa Intel Graphics (ARL)；Node 24.18.0、pnpm 11.25.0、Google Chrome 158.0.8127.36、Playwright 1.65.1。Chrome 无头实际进程使用 `--use-angle=swiftshader-webgl`，即软件渲染，不代表本机硬件加速或实体手机表现；实体手机未测。三个视口 1440×900、768×1024、390×844 各配浅/深主题，桌面 DPR 1、模拟移动 DPR 2；每个桌面组合三次，移动组合一次。串行运行，机器未进行专门负载隔离，Vite 首次编译和系统调度影响就绪时间。

复现：在 `frontend/` 执行 `pnpm install --frozen-lockfile` 后运行 `pnpm exec playwright test --config playwright.map-baseline.config.ts`。配置继承现有合成 UI 服务；每次 `BASELINE` 行输出各次结果。需要本机 Chrome、空闲 5191/8191 端口；缺少 Long Task API、就绪信号、足够帧或全球地图视图变化会明确失败。

就绪耗时从 Playwright 导航开始到可见 ready 标记（含驱动与页面启动），不是纯 GPU 首帧。全球图先拖拽和滚轮，再点击投影按钮；从按钮点击事件起，逐帧观察渲染后的 altitude/yaw/pitch/pan，看到移动后连续 250ms 不变才判为收敛，最多 8s。表中的切换值是最后一次观察到的坐标变化时间；实际确认收敛还需约 250ms。后续采样只在确认后开始。该代理不能证明隐藏的 shader morph 已完成，故应结合实现与记录的轨迹验证，不是浏览器原生动画完成事件。

交互采样由脚本连续拖动、滚轮，移动模拟再通过 CDP 注入双指缩放与中点位移；浏览器 rAF 时间戳记录帧间隔，PerformanceObserver 记录主线程 `longtask`。每行的均值、p95、最长、数量均是该次采样的浏览器观测值；`>33.34ms` 是长帧间隔数量，不是浏览器报告的精确掉帧数，精确合成器掉帧未测。长任务仅计该交互窗口，回调调度与窗口边界可能影响计数。不同组合的采样帧数/持续时间不同，长任务总量和长间隔计数不宜直接作吞吐对比。

## 候选问题与下一步

1. **软件渲染下全球 2D 交互可能卡顿。** 在上述三次桌面重复中，查看各组合的 2D p95 与长任务列；步骤为复现命令、打开 `/dashboard`、拖拽滚轮后切到 2D，待坐标稳定后再连续平移缩放。优先以硬件加速 Chrome、实体手机和浏览器 Performance tracing 复测，并分离 Three.js 绘制与玻璃效果的代价；当前证据不能归因或推广到硬件 GPU。
2. **投影切换的可观察完成边界不足。** 代码的按钮状态在开始时变化，视图动画约 1100ms，立即输入会提前结束过渡；不要把按钮状态变化当成动画完成。建议独立验证现有坐标收敛代理与实际 morph 绘制结束的一致性，并考虑提供无副作用的明确完成信号。
