# 81 跑步记录的“列表 / 足迹墙”视图

日期：2026-11-02。

## 起因

“足迹墙”（`/activities/wall`）和“跑步记录”（`/activities`）读取同一批记录（同一个 `readActivities`），都是每次跑步一张带路线缩略图、日期、标题、距离和用时的卡片，区别只有：墙的网格更密，页头多一个“生成分享图”；列表带导入与批量管理。同一批数据在主导航里占两个入口，数据汇总页还有一份近期预览。

## 使用方式

- 主导航不再有“足迹墙”。`/activities` 与 `/activities/wall` 都点亮“跑步记录”。
- 两个页面的页头下方有同一组分段切换（`ActivityViews.svelte`，`.settings-tabs` 链接，`aria-label="跑步记录视图"`）：**列表** / **足迹墙**，当前项用 `aria-current="page"`。
- 列表页去掉了“查看足迹墙”按钮；足迹墙页去掉了“返回跑步记录”按钮，保留“生成分享图”。
- 两个页面各自的标题（“跑步记录”“足迹墙”）、地址、公开主页与工作区下的同名地址都不变，所以旧链接、站点地图和展示页都继续有效，没有重定向。数据汇总页的“近期足迹墙”预览和“查看全部足迹”入口保持原样。
- 列表视图的样子见 [82](82-activity-timeline-preview.md)（时间线加桌面预览栏）。
- 副作用：主导航最多 8 个入口，原本为 9 个入口准备的“始终只有图标”模式（`data-dense`）没有账户触发，已删除；实测普通账户（最后一个入口“本人工作区”文字最长）在 1360px 带文字也不压到账户区。

## 接口与隐私

只涉及前端导航与页面外壳，没有后端、接口、数据库、鉴权或公开数据边界的改动；没有新增请求。
