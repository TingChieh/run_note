# AI 分析设备指标升级

2026-10-15 完成并加载到本机后端，无新增数据库迁移。

## 使用

导入含平均心率、热量或步数的 TCX 后，打开“AI 跑步分析”，选择日期范围并读取统计依据。页面会显示整体和每周设备指标，以及各指标的覆盖记录数。确认新的数据发送说明后，手动生成分析；读取、刷新和查看历史均不会自动调用供应商。

旧报告保留生成时的内容和统计快照。页面提示旧版快照未包含设备指标，需要手动生成新报告才能利用新增数据，不会自动覆盖或重新扣额度。

## 统计口径

- 平均心率按同时具有平均心率和正有效用时的记录加权；用时优先设备 `timer_seconds`，缺失时才回退到 `elapsed_seconds`。设备用时为零时不回退、不参与心率加权。展示心率覆盖数和实际参与加权数，明确这是由活动平均值计算的估计，未重算逐点心率。
- 热量与步数仅累计已知记录，标记为“已知记录小计”，展示覆盖数。有效零值计入覆盖率；完全无数据则为 null 并显示“暂无数据”，不显示为零。
- 按活动本地日期分周，日期范围左含右不含。总平均心率根据原始加权和计算，不对周平均值再次做简单平均。
- GPX 或历史记录缺少新指标时仍计入跑量、频率和配速，不补造心率或其他设备数据。

## AI 与隐私

新快照版本为 `running-summary-v2`，在顶层和每周条目中增加 `device_metrics`；旧 summary 结构不变，客户端仍支持 `running-summary-v1`。现有 JSON 报告存储可直接兼容，历史内容不重新计算。

提示词版本为 `running-qualitative-v2`。AI 可解释汇总心率和配速各自的变化，必须考虑覆盖率；没有活动配对和可比训练条件，不能声称心率与配速对应、相关或有因果关系。不能由平均心率推断心率区间、最大心率、疾病或训练过量，不能由总步数推断跑步步频，也不能把设备热量当作精确消耗。数值仍由后端事实面板展示，模型保持定性输出校验。

供应商请求在整体及每周层级重建设备指标白名单。新增指标仅发送必要汇总，不发送原始 GPX/TCX、GPS 坐标、逐次活动、邮箱、用户名、标题或备注。授权文案已同步增加汇总心率、热量、步数及覆盖率；沿用手动触发、幂等重试、配额和失败状态管理。
