# RunNote V1.1 UI/UX 改造计划

审查范围：登录/注册、Dashboard、Activities 列表与详情、Footprints、AI、Settings、公开主页及分享页。当前界面以 Tailwind 原子类直接排版，主色为低饱和绿色配灰色；认证、日历、路线图、足迹图、趋势图、分享面板、分析事实和公开活动已有可复用组件。页面整体可用，但导航、间距、反馈、控件状态还没有统一的产品级规则。

## P0：建立一致的应用框架

- **页面：** 所有登录后页面及公开页面。**文件：** `frontend/src/routes/+layout.svelte`、`frontend/src/app.css`。
- 定义 RunNote 的品牌色阶、语义色、正文/标题层级、间距、边框和焦点样式；目前背景、前景、绿色主色已集中为 CSS 变量，可在此基础上扩展，不另起一套页面颜色。
- 桌面端固定清晰的主导航与当前页状态；移动端收为可键盘操作的导航菜单，避免当前导航和账号信息在窄屏换行挤压。
- 统一内容宽度、页面标题/说明/主操作的位置，以及 `loading / empty / error / success` 的反馈样式。优先抽出轻量 `PageHeader`、`FeedbackState`、`MetricSummary` 等共享组件；不引入大型组件库迁移。

## P1：优先打磨跑步记录主流程

- **Activities 列表/上传：** `frontend/src/routes/activities/+page.svelte`。将上传表单做成更紧凑的主操作区；列表以可扫描的日期、距离、时长、配速和可见性组织；清晰显示解析进度、质量警告、重复记录入口及可重试错误。保留原有上传和重复检测行为。
- **活动详情：** `frontend/src/routes/activities/[id]/+page.svelte`、`RouteMap.svelte`、`SharePanel.svelte`。让核心指标先于次要质量字段；地图获得稳定的响应式高度和明确的地图状态；分享可见性、链接创建和撤销采用一致的操作与结果反馈。
- **反馈复用：** 将上述页面重复出现的状态文字和重试入口收敛到 P0 的共享反馈组件，保持 `aria-live`、`role=status/alert` 和键盘焦点可见。

## P1：让日历、图表和地图更易读

- **Dashboard：** `frontend/src/routes/dashboard/+page.svelte`、`CalendarGrid.svelte`、`TrendChart.svelte`。统一年度摘要和日历/趋势筛选的位置；日历保持横向可滚动但增加清晰月份刻度、强弱图例和选中日状态；日历键盘交互改为网格方向键导航，避免逐格 Tab 穿过全年日期。图表在窄屏减少标签拥挤，保留现有可访问数据表和减少动画偏好。
- **Footprints：** `frontend/src/routes/footprints/+page.svelte`、`FootprintMap.svelte`。把日期范围、路线/热力模式和过滤条件组成稳定工具栏；地图高度随视口调整；强化图例、所选路线状态与重叠路线列表之间的对应，并让地图上的信息也能从列表键盘访问。减少地图上叠加控件遮挡路线的情况。

## P2：表单、分析和公开页面细节

- **登录/注册：** `AuthForm.svelte`、登录与注册路由。保持共享表单和现有认证协议；整理字段说明、密码显隐按钮、提交中状态及错误关联，确保错误聚焦与屏幕阅读器播报。
- **AI 分析：** `frontend/src/routes/ai/+page.svelte`、`AnalysisFacts.svelte`。把日期范围、统计依据、用户同意、生成操作和报告历史分组；让未配置、空数据、处理中、失败、过期快照和删除成功状态更易区分。保留现有最小数据披露及明确同意步骤。
- **Settings：** `frontend/src/routes/settings/+page.svelte`。将账户信息与公开主页设置分区；把主页开关的影响贴近控件呈现；增加未保存/保存中状态，避免用户误以为每次改动立即生效。
- **公开主页和分享：** `frontend/src/routes/u/[username]/+page.svelte`、`PublicActivityPage.svelte`、分享与公开活动路由。复用统计、日历、活动指标的版式；清楚标明公开数据范围和链接状态，增强无记录、关闭主页、失效链接状态的一致性；继续隐藏私人数据与精确路线。

## 建议顺序

先完成 **P0 全局框架与反馈规范**，随后首先改造 **Activities 列表/上传和活动详情**，因为这是导入、查看地图、管理分享的连续主流程。再做 Dashboard/Footprints 的可视化和键盘体验，最后处理 AI、Settings 与公开页面细节。每个阶段保留现有 API 和业务契约，以桌面、窄屏、键盘及屏幕阅读器检查作为设计验收项。
