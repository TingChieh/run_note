# 开发阶段与验收标准

> 本文是分阶段开发与验收基线。2026-10-12 已将开发、测试和部署统一调整为非容器化；阶段一真实结果见 07-phase-one-implementation.md，后续阶段仍未实施。

## 1. 阶段关系与统一完成规则

```mermaid
flowchart LR
    S1[1 环境与骨架] --> S2[2 认证 GPX 持久化]
    S2 --> S3[3 记录管理 单次地图]
    S3 --> S4[4 日历与统计 核心MVP]
    S4 --> S5[5 叠加与空间热力]
    S5 --> S6[6 公开主页与分享]
    S6 --> S7[7 AI辅助分析]
    S7 --> S8[8 回归 部署 毕业交付]
```

所有阶段都必须同时满足：

1. 本阶段任务全部实现，未实现项明确列为未通过，不能用设计截图替代功能验收。
2. 新增核心规则有自动化测试，相关回归测试通过；命令、环境、时间和实际结果保存为证据。
3. 后端鉴权、参数、错误规范和敏感配置符合前述设计；前端类型检查与构建通过。
4. 本阶段DB变更有Alembic迁移，从前一阶段数据库升级并验证数据保留；DB相关集成测试使用PostGIS。
5. README、API、数据模型及决策与实际实现一致；保留一次可重现演示及必要截图。
6. 没有未解决的P0正确性/权限问题；P1问题记录影响与处理阶段。

“完成”指代码、测试、数据、文档与演示均达到该阶段验收条件，不只是页面能打开。不得把后续阶段的功能提前当作前阶段必须完成的门槛。

## 2. 阶段一：项目骨架、开发环境与数据库

### 开发任务

- 按架构文档创建frontend、backend、infra与测试目录，此时才初始化Git和忽略规则。
- 验证并锁定SvelteKit/Svelte5、Tailwind、shadcn-svelte、Python/FastAPI/SQLAlchemy/PostGIS兼容版本，保存安装方式与锁文件。
- 核对 Homebrew PostgreSQL/PostGIS 兼容版本、原生数据目录与健康检查；使用 Python 独立虚拟环境和 pnpm 锁定依赖，前后端热更新与 Vite 同源 API 代理。
- 环境变量启动校验、统一响应/异常、request_id、脱敏日志与DB连接Session生命周期。
- 初始化Alembic，迁移启用PostGIS；此阶段不必提前创建后续业务表。
- 提供 live/ready 接口及独立 PostgreSQL/PostGIS 测试数据库，建立后端测试、前端检查和构建流程；GitHub CI 使用原生 Homebrew 临时测试集群，不使用容器。
- 保存架构决策、运行说明、依赖版本，补充实际OpenAPI基线。

### 明确完成标准

- [ ] 全新环境依据README能安装依赖、启动DB/前后端并看到最小页面，无手工改源码才能运行的步骤。
- [ ] `/api/v1/health/live` 为 200；数据库、扩展与迁移就绪时 `/api/v1/health/ready` 和 `/api/health` 为 200，独立测试实例断开后 ready 为 503 且不暴露连接信息。
- [ ] 独立空测试库执行迁移成功；PostGIS 空间函数可调用；在独立受控原生实例写入测试数据，正常停止/启动后重读数据和 Alembic 版本一致。不得为验收清空、重建或擅自重启日常数据库。
- [ ] 开发浏览器请求走同源 `/api`（业务版本前缀 `/api/v1`；第一阶段健康兼容入口 `/api/health`）；生产 Cookie/Origin 规则已设计，但不宣称开发 HTTP 等于 HTTPS 验证。
- [ ] `.env`被忽略，示例不含密钥，缺少必填配置会明确拒绝启动。
- [ ] 依赖锁、类型检查、最小后端检查和生产构建实际通过，记录所用命令。

Docker/Compose 启动、镜像与容器卷持久性不属于项目任务或验收条件。原生数据持久性、全新环境复现、迁移与自动化测试仍为必需证据。CI 远端执行与本地通过分别记录。

**交付物**：可运行原生环境、初始迁移、健康检查、README 启动与验证步骤、版本表、原生持久性与检查记录。

## 3. 阶段二：用户认证、GPX解析与持久化

详细规划见 [第二阶段技术方案与实施计划](08-phase-two-implementation-plan.md)。该文档补充 Haversine 对照算法、时间异常细则、当前骨架适配和逐步验收；权威距离仍沿用 PostGIS geography。当前只完成规划，没有执行阶段二代码或迁移。

### 开发任务

- 迁移建立用户、会话、认证限流、活动、成功GPX来源、段与点表及唯一/外键约束。
- 实现注册、登录、登出、个人资料、修改密码、预认证CSRF、绝对/闲置过期和登录限流。
- 实现原文大小与XML安全校验、gpxpy解析、坐标与时间质量、分段/异常断边、PostGIS测距及配速。
- 固定gpx-v1与指纹v1，保留原文，支持带补录日期的无时间轨迹。
- 实现同步受限导入、重复冲突、全事务写入、用户内与跨用户隔离。
- 建立正常/异常GPX样本库和预期值；冻结后续统计使用的指标字段及单位。

### 明确完成标准

- [ ] 能注册、登录、登出；密码不是明文，登录换会话，旧会话/过期会话不可访问；CSRF或来源不合法的写入被拒绝。
- [ ] 本阶段认证、导入和活动归属查询的已实现入口严格按owner校验；A不能读取B的导入结果；伪造owner无效。完整CRUD与route越权矩阵在阶段三验收。
- [ ] 正常GPX导入能在DB同时找到原文、摘要、有效点与连续段；所有实体归属一致。
- [ ] 多trk/trkseg、单点段、重复点、非法坐标、缺高程、缺/无偏移时间、时间倒退、跳点、长缺测和零距离样例按文档规则处理。
- [ ] 不跨段/异常边测距；含NULL时间不会得到伪造耗时或配速；缺可靠开始时间需用户日期，不使用导入日期。
- [ ] 同用户原文重复和完整时间语义重复返回409；并发重复只有一条活动；不同用户可独立导入同文件。
- [ ] 非法XML/DTD/实体、无有效点、超字节/点/段/预算均得到确定错误；失败无残留半条活动。
- [ ] 固定测距样例达到风险文档中的误差标准；记录实际导入耗时、点数及质量摘要。

**交付物**：可调用认证/导入API、迁移、算法说明、样本库、核心单元与集成测试报告。

## 4. 阶段三：单次地图与记录管理

### 开发任务

- 创建记录列表、日期/来源/隐私筛选、分页、导入页面、详情与手动创建页面。
- 实现允许字段编辑、手动指标重算、删除级联与数据版本更新。
- 确定MapLibre底图样式/瓦片/字体来源、署名与配额；确认目标网络能访问。
- 返回有权限的路线、单点、起终点、bounds；实现分段绘制、fit bounds与指标信息面板。
- 固定显示简化算法、zoom档位与响应点数上限，验证不修改权威距离。
- 实现地图加载失败状态、空路线状态、错误与质量提示，销毁地图实例。

### 明确完成标准

- [ ] 用户可从浏览器完整完成登录→GPX导入→列表→详情→轨迹查看，不依赖直接操作DB。
- [ ] 手动创建/编辑后指标正确，手动记录显示无轨迹；GPX只读指标不能被PATCH覆盖。
- [ ] 日期筛选边界与稳定分页正确；删除后列表、原文、点与段均不存在，用户数据版本递增。
- [ ] 多段/断点地图不画连接线，起终点由完整有效数据得到；单点和跨±180°路线有可解释展示。
- [ ] 简化前后distance_m完全相同；坐标顺序正确；最小段端点/大响应受限，超限有提示。
- [ ] 瓦片服务不可用时仍可阅读记录与指标；地图许可署名可见，服务地址不泄露私人数据或后端密钥。
- [ ] 浏览器E2E覆盖正常闭环与A/B用户隔离，前端构建/类型检查通过。
- [ ] A查询/编辑/删除B的活动和route全部404，B数据不变，覆盖全部已实现CRUD入口。

**交付物**：记录管理与单次地图UI、API、地图资源决策、E2E记录与截图。

## 5. 阶段四：年度日历与统计图表

### 开发任务

- 实现全年日格API、年份及距离/次数维度切换、日格提示与当日列表跳转。
- 实现日期范围内汇总及自然周/月/年趋势，ECharts里程、次数、时长、配速展示。
- 将coverage与质量警告传至界面，缺失配速留空，不用0连线误导趋势。
- 使用活动日期索引，从摘要聚合，验证公开/私人数据访问边界的查询基础。
- 建立闰年、跨年、跨午夜、夏令时、空年份、不同运动来源和部分耗时样本。

### 明确完成标准

- [ ] 365/366天完整，周起点为星期一；切年、切维度、日格提示与当日记录一致。
- [ ] 固定样本的日/月/年次数、距离和已知耗时可人工核算一致；自然周部分桶被标记。
- [ ] 配速是合格子集的总耗时/总距离，不能平均单次配速；未知耗时活动不会拉低配速。
- [ ] 改默认时区不移动历史日格；跨午夜整次归开始日，UTC耗时不受夏令时影响。
- [ ] 空年份显示已知0次/0距离、暂无耗时/配速，不产生NaN或前端异常。
- [ ] 固定性能基线上列表、汇总与年度日历达到冻结目标；未达标不能仅凭瓶颈报告通过，调整目标须有实测依据与文档修订并重新验收。
- [ ] 核心MVP演示闭环和对应测试完成；当前阶段一至四的需求覆盖矩阵有实际证据。

**交付物**：可用核心MVP、日历与图表、统计口径说明、核算数据和第一轮性能报告。

## 6. 阶段五：轨迹叠加与空间热力图

### 开发任务

- 实现本人时间范围、viewport和zoom筛选下的轨迹叠加。
- 基于有效段与固定投影网格计算distinct活动次数，处理单点与边界规则。
- 建立GiST空间查询，限定活动数、输出点/格数、日期跨度与网格尺度。
- MapLibre展示网格颜色与图例，说明计数模式和投影尺度。
- 测量高采样、绕圈、重复线路、日期变更线和极端纬度样例，不提前增加缓存层。

### 明确完成标准

- [ ] 用户可叠加筛选范围内完整候选活动；私有数据只向本人返回。
- [ ] 同活动重采样/绕圈同格只计1，两次不同活动同格计2；原始频率可复核。
- [ ] 不以简化显示点/轨迹点密度代替经过次数；响应口径、最大计数与图例一致。
- [ ] 边界/单点/跨日期变更线处理稳定，纬度超适用范围有明确提示而不改变活动指标。
- [ ] 超上限请求返回标准错误，没有静默截断或空白假结果；热力图性能达到冻结目标。确需修订目标须记录实测依据并重新验证，失败报告不能代替通过。
- [ ] 多用户隔离与计数测试通过，记录EXPLAIN/实际运行及空间索引效果。

**交付物**：叠加/热力UI、空间算法说明、边界样本、空间查询测试与性能记录。

## 7. 阶段六：公开主页与分享

### 开发任务

- 增加分享链接迁移与专用公开响应模型；实现主页开关和private/unlisted/public状态。
- 实现public活动页、链接创建/撤销/到期、独立共享轨迹开关与公开预览。
- 公开主页及汇总仅查询public活动，不能复用本人全历史汇总。
- 实施no-store、noindex、Referrer-Policy与token日志脱敏。
- 建立匿名、本人、他人、有效/失效令牌、隐私切换的权限矩阵。

### 明确完成标准

- [ ] 新账号、新活动、新共享轨迹默认关闭；开启主页不自动公开任何private/unlisted活动。
- [ ] public匿名可见；unlisted仅有效token可见；private仅本人可见，未知/不可见均404。
- [ ] 公开摘要不含坐标、起终点、原始GPX、邮箱、备注、精确时间或内部owner；route单独校验授权。
- [ ] 撤销、过期、改private、删除活动或关闭轨迹后，下一次相关匿名请求立即失败；再公开不恢复旧token。
- [ ] 关闭主页不误宣称所有活动分享已取消；界面提示公开坐标的实际暴露与撤销边界。
- [ ] token不进入访问/错误日志或外链Referer；无共享缓存延长暴露，所有权限矩阵测试通过。

**交付物**：公开/分享UI与API、迁移、权限矩阵、安全回归结果和匿名视角截图。

## 8. 阶段七：AI辅助分析

### 开发任务

- 增加报告表、请求幂等/并发/额度约束与过时判断。
- 复用统计服务创建一致快照，用户明确同意后仅发送汇总。
- 接入一个已验证兼容的模型供应商，固定base URL、模型、prompt版本、预算与deadline。
- 实现succeeded/failed状态、遗留pending回收、用户主动重试、报告查看/删除正文。
- 事实面板与文字分开显示，以纯文本或安全Markdown呈现，不让AI改变记录。
- 先用Mock供应商自动化测试，再进行不含私人坐标的受控真实调用与人工质量评估。

### 明确完成标准

- [ ] 无同意不调用供应商；出站请求不含坐标、原文、标题/备注、身份、分享链接或他人数据。
- [ ] 输入中的全部数值来自后端统计并能由快照复核，页面事实面板不受AI文字修改。
- [ ] 调用记录保留期间，相同幂等键不重复计费调用，已完成重放不受新额度/pending误拦；不同worker同用户最多一个pending；失败/删除报告的尝试均计入额度。
- [ ] 超时、断网、429、5xx、错误JSON和超长响应形成failed状态与标准错误，不破坏记录或统计。
- [ ] 遗留pending可以按期限转failed，迟到结果不覆盖；用户主动新key重试，服务器不自动重发。
- [ ] 活动数据变化后旧报告is_stale=true；他人无法查看/删除报告，公开主页无AI内容。
- [ ] 评估覆盖训练量上升、下降、稀疏数据、缺耗时、质量异常五类，记录事实错误与建议边界；事实编造案例不能标记通过。

**交付物**：AI页面/API、统计快照、迁移、供应商配置说明、Mock测试与人工评估报告。

## 9. 阶段八：回归、性能、部署与毕业文档

### 开发任务

- 执行全部核心单元、PostGIS集成、权限矩阵与浏览器E2E回归；补齐故障注入。
- 在固定基线重测导入、列表、地图响应、统计和空间查询；只对实测瓶颈加索引、批量写入或简化优化。
- 完成 Linux 原生 PostgreSQL/PostGIS、Python 虚拟环境与 pnpm 发布流程；由 systemd 管理 Node/Uvicorn，Caddy 提供 HTTPS；验证可信代理、配置校验、端口隔离、健康检查和日志策略。
- 执行空库迁移、已有数据升级、备份恢复和版本回滚演练，记录实际数据与指标核对结果。
- 完成部署/运维说明、用户手册、测试报告、论文设计材料与答辩演示脚本。
- 公网开放注册前补邮箱验证/找回与必要滥用控制；若未做则限定本地或受控演示部署并明确真实能力。

### 明确完成标准

- [ ] 核心自动化测试无失败，P0功能与权限问题为零；剩余限制如实写入最终报告。
- [ ] 固定硬件/数据/并发下的p95达到冻结目标，内存、DB大小与查询证据完整，不把外部瓦片/AI耗时混入本地指标；目标变更有实测依据且已重新验证。
- [ ] Linux systemd 的应用启动、失败恢复及受控重启可用；HTTPS 可用，生产 Cookie 安全属性正确，DB/API 不直接公网暴露，日志与产物中无密钥/原文/token。
- [ ] 全新目标机器按部署说明可复现，数据库备份在空库恢复后活动、轨迹、统计和权限抽查一致。
- [ ] 数据迁移升级保留原记录；已说明不能无损downgrade的变更使用恢复方案，不能承诺所有迁移可逆。
- [ ] 需求—模块—API—测试—论文章节对应完整；ER图、算法版本、截图与实现一致，未实现功能不写成已完成。
- [ ] 答辩演示包含正常导入、异常/重复处理、地图、日历、权限和已实现扩展，并预备离线样本/Mock AI避免外部服务中断演示。

**交付物**：生产配置、可复现部署与恢复说明、最终测试/性能报告、用户手册、论文图表与答辩脚本。
