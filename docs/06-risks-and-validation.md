# 技术风险、测试与毕业交付

## 1. 必须优先解决的风险

P0为进入相关阶段前必须关闭的风险，P1为实现该能力时必须验证，P2为规模增长后评估。以下性能值均是验收目标，不是已经跑出的结果。

| 优先级 | 风险及后果 | 处理与验证 | 最迟阶段 |
| --- | --- | --- | --- |
| P0 | 度数当米、跨段连线、缺时间当0使指标失真 | geography测距、断段、NULL语义；固定黄金样本核算 | 2 |
| P0 | 路线/记录接口越权或公开模型泄露坐标 | 查询绑定owner、公开白名单、路线独立授权、匿名矩阵 | 2；公开前6 |
| P0 | GPX实体扩展、超大文件、CPU与内存失控 | 安全XML预检、逐层限额、deadline、必要进程隔离，恶意样本压力测试 | 2 |
| P0 | 导入半提交、并发重复、段点不一致 | 唯一/复合外键、原子事务、故障注入与并发测试 | 2 |
| P0 | 认证会话固定/CSRF/伪代理头/多worker限流失效 | 令牌轮换、会话绑定CSRF、来源检查、受控代理、DB原子桶 | 2 |
| P0 | 时区、跨年和加权配速口径不一致 | UTC时间+活动日期快照、自然桶、配速合格子集，边界样本 | 2定义；4验证 |
| P0 | PostGIS迁移权限或依赖组合不可用 | 空库扩展/迁移实验，记录兼容的原生 PostgreSQL/PostGIS 包和运行时版本 | 1 |
| P1 | 地图样式/瓦片/字体不通或无合法许可 | 确定资源、目标网络实测、署名、失败降级，禁止公共OSM瓦片充当无条件免费CDN | 3 |
| P1 | 大轨迹响应、批量点写入或热力查询慢 | 摘要查询、批量插入、显示简化、GiST与范围上限；先实测再优化 | 3、5 |
| P1 | 经过频率被采样率或绕圈次数误导 | 每活动每格distinct计数、固定边界规则、重采样同值测试 | 5 |
| P1 | 公开后撤销不生效、令牌进入日志/Referer | no-store、动态检查、隐私变更撤销、日志脱敏、匿名复测 | 6 |
| P1 | AI幻觉、私密数据外发、费用与遗留pending | 最小摘要、明示同意、快照、幂等/额度/deadline、状态回收与Mock | 7 |
| P1 | 源码与生产配置泄露、备份无法恢复 | 环境变量、端口隔离、HTTPS、独立恢复演练、实测升级 | 8 |
| P2 | 原文与点数据使DB备份变大 | 记录原文/点/索引占用、备份窗口和磁盘阈值；证据充分才迁移存储 | 8及后续 |

推荐最先完成四项技术验证：依赖与PostGIS可用；真实GPX样本的指标算法；同源Cookie/CSRF与SSR传递；底图资源可用。这些验证在各阶段实施，不在本轮生成实验程序。

## 2. 测试分层

| 层级 | 测什么 | 工具/环境建议 | 不替代什么 |
| --- | --- | --- | --- |
| 单元 | 规范化、时间状态、指纹、配速、范围校验 | pytest与小型内存样本 | 真实PostGIS计算与事务 |
| 集成 | DB迁移、geography距离、约束、级联、聚合、权限、并发 | pytest/httpx + 独立PostgreSQL/PostGIS | 浏览器Cookie/地图交互 |
| 前端组件 | 日历空态、NULL指标、质量提示、隐私选择 | Svelte兼容测试工具 | 后端指标正确性 |
| 浏览器E2E | 登录导入管理、地图、日历、分享匿名、退出数据清理 | Playwright，至少Chromium | 大规模性能或地理测量准确度 |
| 性能/故障 | 上传限额、超时、查询p95、内存、依赖断开 | 可复现负载脚本 + Postgres查询计划 | 功能正确性与许可审查 |
| AI评估 | 输出事实一致、建议边界、稀疏数据处理 | Mock自动化 + 固定案例人工审阅 | 模型不会幻觉的保证 |

核心计算与授权测试必须有独立预期值/攻击情景，不能只照着实现重写一遍或只断言HTTP200。无需为样式间距、文案替换等低影响改动写机械测试。

## 3. GPX黄金样本与预期规则

固定样本使用可公开合成/脱敏数据，提交到测试目录时避免真实住址坐标。预期值、规则版本和来源写入样本说明。

| 样本 | 预期结果 |
| --- | --- |
| 六个赤道等间距点，总经度差0.01°，每120秒采样，总600秒 | WGS84椭球距离约1113.194908m，耗时600秒，配速约539秒/km；非实现函数自行生成期望 |
| 两个间隔很远的trkseg | 仅各段内部距离之和，无段间连接；总耗时在时间完整时含间隔 |
| 多trk、一段单点 | 一条活动，多段；单点段距离0、可以展示Point |
| 同位置同时间同高程重复点 | 相邻重复去除并计数，指标不变 |
| 同位置不同时间停留 | 点保留，距离不增加，总耗时增加 |
| 中间非法坐标 | 该点丢弃、前后分段，不产生桥接距离 |
| 部分缺时间/无时区偏移 | 路线与距离可用，总耗时/配速NULL，质量提示；无started_at需补日期 |
| 时间倒退/正位移零时间差 | 断边并标时间invalid，总耗时/配速NULL，不排序修复 |
| 速度跳点/300秒以上缺测 | 拒绝相邻边、保留分段与警告；不连接两侧补距 |
| 仅两点、经度差0.01°、时间差600秒 | 超300秒断边为两个单点，距离0、总耗时600秒、配速NULL |
| 无高程 | 距离不变，不生成爬升值 |
| 零距离/零耗时 | 非负值保留，配速NULL，不除零或返回Infinity |
| 相同文件/不同XML格式相同可信点 | raw/canonical规则分别触发用户内重复，原活动不新增 |
| 同路线不同日期/不完整时间近似路线 | 可成为不同活动，不用模糊距离强制去重 |
| 空XML/无trkpt/rte-only/恶意DTD实体 | 确定错误、不访问网络或文件、无活动入库 |
| 超10MiB/50000点/1000段/处理预算 | 对应超限/超时错误，资源释放，后续正常请求可用 |
| 跨±180°/高纬路线 | geography测距正确；地图不横穿世界；热力超适用纬度明确拒绝 |

建议独立采用WGS84参考值或权威地理工具产生黄金数据，不另引入一个线上测距库。持久化距离对参考值误差≤max(1m,参考距离×0.1%)；同输入重复运行的结果需在舍入精度内一致。坐标GPS本身的实地误差不能用上述算法误差指标消除。

时间差误差≤0.001秒（按毫秒持久化），配速允许同样舍入传播。摘要到聚合的差异只来自规定的舍入，不允许前端换算法。数据库、参考公式与UI单位分别核验。

## 4. 日期、统计与权限测试

日期样本至少覆盖2024年闰日、空年份、12月31日跨午夜、UTC与Asia/Shanghai跨日期、America/New_York夏令时切换。耗时使用UTC差，activity_date根据活动时区；修改账号时区不改变旧日期。

统计黄金集合建议包含：5km/1800秒、10km/3000秒、3km/NULL耗时、0km/600秒各一条。总次数4、距离18km、已知耗时5400秒、known_duration_count=3；配速合格2条/15km/4800秒，汇总320秒/km。零距离已知耗时可以进入已知耗时和次数，但不进入配速。这组数据能检出平均单次配速、全部距离除部分时间等错误。

权限自动化矩阵至少包含：

| 情景 | 必须观察到的结果 |
| --- | --- |
| A登录读取/编辑/删B的ID、route和share管理 | 全部404，B数据不变 |
| 客户端传user_id/source/avg_pace | 422，无归属或指标覆盖 |
| 缺/错CSRF，恶意Origin，伪造代理IP | 写入拒绝；IP以受控代理结果为准 |
| 匿名/private、无token/unlisted | 404，不泄漏存在性或路线字段 |
| public摘要、allow_shared_route=false | 摘要白名单可见；两类route接口均404 |
| 主页开启但含private/unlisted历史 | 公开列表和公开汇总都不包含这些记录 |
| 令牌到期/撤销/活动private/删除 | 下一次访问404；重新公开不复活旧链接 |
| SSR交替访问两个用户 | 页面、缓存、服务端模块无交叉身份泄漏 |
| 退出后浏览器返回上一页 | 本人数据状态清理，不能再次从API读取 |
| 跨worker登录/导入/AI同时请求 | 限流/重复/单pending约束有效，没有只在单进程成立的保护 |

## 5. 性能验收基线

第一阶段确认可用硬件，第四阶段首测并冻结环境，后续沿用。初始建议：Linux 原生目标机 2 vCPU、4GiB 内存，应用与DB同机，本地API网络；两名测试用户合计1000条活动、平均3000点/条，其中一条50000点，时间跨度5年。

记录OS、CPU、内存、磁盘、PostgreSQL/PostGIS版本、Uvicorn worker数、连接池、样本生成seed、活动/点/段数、raw/索引占用、请求列表和客户端位置。冷缓存与热缓存分开；p95须来自至少100次相同规模请求，5并发读取，不能用单次最快值。

| 操作 | 初始目标 | 验证边界 |
| --- | --- | --- |
| 列表20条、summary、年度calendar | p95≤1秒 | 不含前端加载与外部网络 |
| 单条route，约3000源点、≤5000显示点 | p95≤2秒 | 包含后端序列化，不含瓦片下载 |
| 3000点普通GPX | p95≤3秒 | 单导入流，含校验、计算和事务提交 |
| 50000点极限GPX | ≤15秒解析预算、整体≤20秒 | 不得突破内存或导致其他用户请求不可用；不能以延长预算掩盖失败 |
| 叠加100条/总显示≤50000点 | p95≤3秒 | 记录实际JSON体积与地图渲染耗时 |
| 热力100条、默认250投影米、输出≤20000格 | p95≤5秒 | 固定viewport与范围；最坏上限查询单独报告 |
| AI | 服务器调用整体≤30秒或标准超时 | 供应商耗时单列，不承诺文字质量或外部服务稳定 |

这些目标尚未验证。若未达标，先记录EXPLAIN ANALYZE、批量写入、GiST过滤、响应体和内存，针对证据优化。SQLite、空表、Mock距离或本机不同配置数据不能冒充此基线。

极限导入隔离场景固定为：一名用户导入50000点文件时，另一名用户同时运行5并发列表/summary/calendar/route读取，至少100个读取请求；合法读取响应全部200且数据正确、无连接池耗尽/进程崩溃/OOM。该场景读取p95不超过对应常规目标的2倍（列表/汇总/日历2秒、route4秒），解析和整体导入仍受15/20秒预算；记录应用/DB峰值内存和CPU。未通过须优化或正式修订后复测，不能只写“其他请求可用”。

阶段四冻结目标后，以达到目标作为完成条件；确需调整时须记录硬件/数据/业务依据、修改目标并重新验收，单独的失败证据不代表通过。

MVP不先缓存用户统计/公开路线。确需缓存时，必须按owner、筛选、权限与数据版本区分键，公开撤销要立即失效；做不到就保留no-store与按需查询。

## 6. AI验证规则

自动化Mock覆盖成功、空数据、异常JSON、超长输出、供应商429/5xx、连接/整体超时、网络中断、相同幂等键重复、删除不返还额度、进程崩溃遗留pending与迟到完成。

对发往供应商的请求做字段白名单断言，不仅检查UI。AI在短事务先锁用户行，随后读取版本与聚合并创建pending；活动写事务先锁同一用户行再修改数据及版本，阻止聚合查询间出现新提交，快照与版本保持一致。测试注入并发编辑，不能把旧统计标成新版本；外部AI调用发生在提交之后。

固定五类评估案例：训练量上升、训练量下降、记录稀疏、部分缺时、异常轨迹较多。人工核对是否把未知耗时当完整数据、是否编造里程/次数、是否给过度确定的结论。无法可靠核验的数字不显示为事实，事实面板直接用快照。

用户同意的是指定时间范围的最小统计摘要，密钥和供应商URL由服务器配置。未配置AI时页面说明不可用，核心记录、地图和统计仍正常运行；不能要求AI服务成为readiness依赖。

## 7. 生产部署与恢复验证

- Linux 原生部署记录系统包/运行时版本，使用 Python 独立虚拟环境和 pnpm 锁定依赖与构建产物；systemd 管理 Node/Uvicorn，Caddy HTTPS 与同源转发，应用仅内部可达。核实代理上传上限和超时不小于应用预算；不构建容器镜像。
- 在独立受控原生实例验证服务重启后数据库数据与迁移版本保留；不以清空或重建现有数据目录完成测试。环境复现和备份恢复仍需实测证据。
- 用独立受控迁移步骤安装PostGIS/升级schema；部署前备份，应用启动验证schema可用，不执行create_all。
- 使用pg_dump生成一致备份，恢复到全新DB后抽查原文字节哈希、轨迹点数/段数、指标、日历、权限及AI快照。PostGIS扩展版本与恢复权限也须验证。
- 恢复后撤销全部登录会话，避免恢复已登出的旧会话；审查备份后的隐私撤销/删除记录，默认不重新开放旧分享令牌，未确认前将恢复数据的公开状态关闭。
- 明确备份是历史副本。演示基线建议保留7天、每日一份，访问受控；业务删除后历史备份会在到期后消失，不宣称即时擦除备份。
- 定期清理过期会话、认证桶和已隐藏报告的过期调用元数据；不得在AI当天额度窗口内删除计数行。
- 演练应用版本回滚。DB变更不一定可逆；不可无损降级时用备份恢复并说明会失去备份后的写入，不强行写危险downgrade。

上述为本项目必要交付验证，单机演示不声称高可用。邮件验证/找回未完成时，不将受控答辩环境描述成可公开运营账号系统。
