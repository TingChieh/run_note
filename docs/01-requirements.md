# 需求分析与范围

> 设计日期：2026-10-09。状态：设计建议稿；本轮仅编写文档。本文固定后续实现的业务口径，改变口径时需要同时更新数据库、接口和验收用例。

## 1. 目标与使用场景

系统服务于个人跑步数据管理：用户上传 GPX 或手动记录运动，查看路线与指标，检索历史记录，观察年度运动习惯和里程趋势，并主动选择分享与 AI 分析。

毕业设计的价值应体现为一条可复现的数据处理链：**原始 GPX → 校验与分段 → 后端指标计算 → 数据持久化 → 可视化与权限控制 → 自动化测试**。页面数量不能代替计算正确性、数据安全或架构合理性。

### 1.1 基线假设

| 项目 | 明确采用的基线 |
| --- | --- |
| 使用对象 | 普通注册用户；不设计管理员后台、组织租户或复杂角色 |
| 运动类型 | 跑步；一个 GPX 文件生成一条活动，多条 `trk` 合并为该活动的独立轨迹段 |
| 账号 | 邮箱与密码登录；独立用户名作为公开主页标识，MVP 创建后不可改名 |
| 时区 | 注册默认 `Asia/Shanghai`，允许设置有效 IANA 时区；不推测 GPS 地理时区 |
| 导入方式 | 单文件、同步、受限导入；不支持 ZIP、批量后台导入或设备自动同步 |
| 本地开发 | macOS + Homebrew PostgreSQL/PostGIS；Python 独立虚拟环境，前端 pnpm，原生进程热更新 |
| 数据规模 | 性能验收基线见风险文档，所有数值上限为待实测的初始设计值 |
| 公开规则 | 主页默认关闭；活动默认 private；共享轨迹默认关闭 |
| AI 定位 | 用户主动触发的摘要与辅助建议；不计算指标，不提供医疗诊断或自动训练处方 |

这些假设用于消除当前规格空白，不增加必须接入的外部服务。学校模板、目标服务器或真实样本与基线不同，应在对应阶段开始前修订受影响部分。

## 3. 需求遗漏及补充

| 当前遗漏 | 带来的问题 | 推荐补充 |
| --- | --- | --- |
| 距离、耗时、配速定义 | 前端、统计与 AI 结果不一致 | 后端统一计算二维椭球距离、总耗时及其平均配速；估计移动耗时暂不做 |
| 缺少时间的归属日期 | 日历可能误把历史运动计入上传当天 | 用户明确补录运动日期；无法推断时不以导入时间代替 |
| 跨日与时区规则 | 年度日历、周月汇总边界不一致 | 全部里程归属活动开始当地日期，保存活动时区快照 |
| 多段、异常点、时间倒退 | 出现跨段直线、夸大的距离或负耗时 | 保留边界，建立质量标志与版本化清洗规则 |
| 文件规模和失败语义 | 内存被占满、半条活动入库 | 上传大小、点数、段数、处理时长受限；事务成功才有活动 |
| 重复导入的判断依据 | 同一路线不同日期误判；并发重复 | 文件哈希强去重；完整时间的规范化指纹辅助强去重 |
| 公开主页与单条分享的关系 | 开主页即泄露全部历史 | 主页仅含 public 活动；unlisted 只凭令牌访问；private 仅本人 |
| 分享是否包含坐标 | 家庭与办公地点被暴露 | 摘要和轨迹分别授权，默认仅摘要 |
| AI 数据范围、成本与错误 | 泄露坐标、失控调用、无法复现 | 明确同意发送统计摘要；限额、超时、快照与报告状态 |
| 外部地图资源 | 有地图引擎却没有可用底图 | 选定可用样式、瓦片和字体来源，核对许可、配额与署名 |
| 密码恢复、邮箱验证 | 公网账号冒用与无法找回 | 本地答辩 MVP 不接邮件；公网开放注册前补齐邮件验证/找回或明确限定部署范围 |
| 删除与备份 | 删除主表但轨迹、原文、分享仍保留 | 关联级联清理；说明备份保留期与恢复流程 |

## 4. 冲突与解决方式

1. **SvelteKit 服务端能力与前后端分离**：SvelteKit 可进行 SSR 和页面加载，但所有业务校验、统计、认证判定和数据写入放在 FastAPI。禁止在 SvelteKit actions 或 `+server.ts` 再写一套业务服务。
2. **统计完整性与缺失数据**：未知耗时使用 `null`，已知耗时求和必须同时返回覆盖数量。汇总配速只使用距离与耗时均可靠的活动，不使用全部里程去除以部分耗时。
3. **轨迹展示与私人路线保护**：公开摘要可用，坐标、起终点、路线缩略图和原始 GPX 需要独立权限。公开接口禁止复用含全部字段的本人接口模型。
4. **异常过滤与历史可追溯**：清洗结果影响统计，但原文保留；记录算法版本与质量摘要，不静默“修复”时间或插补位置。
5. **全部功能与最小可运行版本**：阶段一至四先形成核心 MVP，阶段五至七依序增加能力。阶段八是交付收尾，不能成为首次测试阶段。
6. **AI 建议与指标可信度**：事实字段由统计服务生成，AI 只生成文字；文字中的数字不回写运动记录，也不作为图表数据。

## 5. 方案权衡与明确推荐

| 决策 | 可行方案及权衡 | 推荐 |
| --- | --- | --- |
| 系统拆分 | 模块化单体：部署、事务简单；微服务：隔离强但引入分布式维护成本 | FastAPI 模块化单体 + SvelteKit 独立前端 |
| 认证 | 数据库会话：撤销直接、依赖现有 DB；JWT：适合多客户端，但刷新与撤销增加状态 | 随机令牌 + PostgreSQL 会话 + HttpOnly Cookie |
| 数据访问 | 同步 SQLAlchemy：调试和事务直观；异步：高 IO 并发有利但混合 CPU 解析更复杂 | 同步 SQLAlchemy 2.x + psycopg，普通 `def` API；AI 使用带超时的同步 HTTP 客户端 |
| 导入执行 | 同步限额：结果直接、故障好处理；任务队列：大文件友好但需队列和任务生命周期 | MVP 同步导入，先限制规模并测量；确有需求再设计异步任务 |
| 原始 GPX | DB bytea：可原子提交与统一备份；文件系统：DB 轻但需处理文件/事务一致性 | 有上限的 bytea，适合演示规模；增长风险与迁移条件见数据库文档 |
| 轨迹表示 | 仅 GeoJSON：简单但点级时间与空间检索弱；仅点表：重建成本高；点 + 分段几何：空间能力与追溯兼顾 | 原文 + 有效点表 + 派生分段 geometry |
| 热力定义 | 点密度受采样率影响；线叠加仅视觉；网格内独立活动计数可解释 | 服务端固定网格，每活动每格最多计一次 |
| 底图资源 | 托管矢量瓦片：接入快但受配额/网络影响；自建：控制强但维护成本高；公共演示资源：可用性无保证 | 配置合法托管矢量样式，阶段三核对目标网络、许可与额度，不自建瓦片服务 |
| 统计存储 | 预聚合表快但需失效机制；按需聚合易保证一致 | 从活动摘要查询聚合；先加索引和查询上限 |
| 日期归属 | 按账号当前时区会移动历史；按活动时区快照稳定 | 保存活动 timezone 与 activity_date，历史不自动迁移 |

新引入的少量辅助依赖必须有明确用途：GeoAlchemy2 支持 SQLAlchemy/PostGIS 字段，psycopg 支持 PostgreSQL 连接，Argon2 库用于安全密码哈希，HTTP 客户端用于调用 AI，pytest/httpx 与浏览器测试工具用于验证。第一阶段核实兼容性并锁定版本，不另外引入缓存平台或队列。

## 6. 核心业务规则

- 一条活动只有一个所属用户；客户端不能指定或修改 owner。所有本人资源请求都在后端按所属用户查询。
- GPX 只采纳 `trk/trkseg/trkpt`；仅包含 route 或 waypoint 的文件返回明确的不支持提示。一个文件合并为一条活动，多段不自动拆成多次运动。
- 手动活动需要日期和非负距离，可补充耗时；不伪造 GPS 路线。配速由后端计算，客户端提交配速会被拒绝。
- GPX 活动可编辑标题、备注、隐私；没有可靠开始时间时可以补正日期。MVP 不编辑轨迹点或覆盖 GPX 算出的距离与耗时。
- 默认距离使用米、耗时使用秒、配速使用秒/公里；前端只进行单位与显示格式转换。
- 周从星期一开始；统计范围采用当地活动日期的左闭右开区间。跨午夜整次活动归属开始日，不按轨迹点拆分。
- 账号修改默认时区仅影响未来导入；有可靠开始时间的活动日期来自该活动时区，MVP 不提供批量改历史时区。
- 一年日历返回 365/366 个日期，零次活动日是已知零，活动内未知耗时仍为 `null`。
- 公开主页只汇总 public 活动；本人统计才包含全部本人活动。分享链接与 AI 报告不出现在公开主页。
- 改为 private、删除活动或撤销分享后，后续匿名请求立即不可见；已被保存的公开内容无法回收。

## 7. 范围控制

本次完整规划九类需求，但不规划实时 GPS、设备账号同步、关注点赞、排行榜、消息推送、管理员平台、多租户、付费、视频、复杂训练计划、微服务、Redis、Celery、Kubernetes 或自建地图瓦片服务。

估计移动时间、海拔爬升、路线匹配、起终点地理遮蔽和原始 GPX 导出可作为后续增强，不能先做这些功能而拖延核心闭环。尤其起终点遮蔽不能替代默认不公开坐标。
